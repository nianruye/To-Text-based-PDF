# D 参数泛化 + ghbq 全量构建验证（t266）

## 结论（no-go）

**D 参数（max_pixels=5644800 + unwarp=1）不能直接落地。**

- **wz4 泛化失败**：8 页 A/D 指标完全相同（TP468/FP146/FN78，P0.7622/R0.8571）；D 对 wz4 没有任何收益。
- **ghbq 文本级收益不能转化为可交付产物**：全量 D 构建页数 104、gate PASS，但：
  - **p97 不再整页贴图**：旧 `ghbq_p97v2.pdf` p97 = image1 + 全文本约1pt；新 D 产物 = image0 + 正常字号（9.96/13.55/17.34pt），违反硬约束；
  - **p97 页码从 85 变成 95**（页脚可见），分页/页码行为变坏；
  - p12 目录仍是点线（不是三栏），且出现 ASCII `,`，目录版式未达标；
  - 与 `ghbq_p97v2.pdf` **94/104 页文本不同**；
  - 所以 D 只适合作为「OCR 文本层候选」，不能直接写 `data/ghbq/ocr_params.json`。

**推荐：不写入 ghbq/wz4 的 `ocr_params.json`；D 参数仅记录为待验证实验。** 若产品侧先修好 p97 贴图守卫与 p12 三栏，再考虑只对 ghbq 重跑。

## 一、wz4 泛化（8 gold 页）

gold: p10/50/100/200/341/400/500/600；A/D 都是本次新调用（同 8 页，单 batch）。

by_class 两书完全相同（关键）：comma 251/0/5、period 103/32/29、quote_open 16/14/20、quote_close 9/25/13、bracket_present 7/0/7。

## 五、go/no-go 与推荐

### ① 是否写入 `data/ghbq/ocr_params.json` / `data/wz4/ocr_params.json`

**No-go：都不写。**

- ghbq：D 造成 p97 贴图丢失、页码 85→95、94/104 页 diff；直接落盘会让全量产物不可交付。
- wz4：D=A，无收益，不该改。

### ② 是否按书型/DPI/扫描质量分档

如果未来产品侧修复 p97/p12 后再试，建议：
- **只对 ghbq 类「小字号标点、低 max_pixels、pitch 高」的书**尝试 D；
- wz4/同类书暂不用 D（无收益）；
- 大书可按页成本分档：小书（≤120页）可整本；大书（>500页）先抽样 20 页再决定。

### ③ 若 go 的后续步骤（当前不 go，仅备查）

1. 先修 p97 守卫（`OCR_GIANT_FALLBACK` / 整页贴图）与 p12 三栏，这两个是前置硬条件；
2. 只对 ghbq 写 D params，8 页+12页回归；
3. 重跑全量 104 页，重建产物；
4. 用新 gold 重出 punct 基线，确认 P/R 提升不是 ASCII/全角归一化造成；
5. 逐页对比 p97/p12/GMPG/页码；
6. 再决定是否推广其他书。
