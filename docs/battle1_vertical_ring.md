## 2. 取数口径（窗口 / 步进 / 参考系 / DPI）

- **列端候选**：OCR 行文本以 1-2 位数字结尾（`[0-9０-９]+$`，排除纯 0 的「〇」页码/卷次）。
  全书 366 处 / 60 页，其中年表段（1682-1741）352 处、段外 14 处。
- **窗口**：**列末 1 格** = `[y1 − step, y1]`（y1 = 该 OCR 行框下缘，pt；step = 本页 n≥8 长列「框高/字数」中位）。
  窗口**不动**：HANDOFF 已实测「列末 2 格」会让检出从 184 掉到 156。
- **主块**：窗口内**面积最大的连通域**（不是「任一通过尺寸窗的分量」——见 §5.4 的反例教训）。
  墨迹阈值 `gray < median(gray) − 20`，与 v1 同源。
- **参考系**：版面格（页 pt），不是字形 bbox；padding = 左右各 1pt、下缘 +1pt。
- **DPI**：工具默认 600dpi（v1 的 184 基线即此口径）；本轮另用 `VERT_RING_DPI=900` 做**同判据复核**，
  两种 DPI 都是 352 处 / 50 页、段外 0（§5.5）。

## 5. 新判据 v2 与双向标定

### 5.1 判据（`src/tools/census_ring_digit.py`，`VERT_RING_CRIT=v2` 默认）

窗口不变（列末 1 格），对**主块**（面积最大的连通域）要求：

```
w ∈ [14.5, 19.5] pt           # 圈的外径（竖排水平方向）
h ∈ [11.5, 19.5] pt           # 沿列方向；下界放宽是因短列窗口会裁掉圈顶 2-3pt（真圈 h_min=12.7）
edge >= 0.20                  # 四边最薄边带有墨（圈的外框；手写数字有一边是空的）
ctr  >= 0.15                  # 圈里必须有墨（挡「〇」页码的空圈）
fill <= 0.85                  # 挡实心团块
0.60 <= w/h <= 1.70
hole 不再参与判据（仅记录）
```

**为什么尺寸窗是判据**：竖排里圈码 = 「圈 + 圈内数字」连成的**一个紧凑主块**，外径约一整格（实测 14.96-18.72pt），
而普通数字字形 8-13pt、两字竖叠最多 w≈13pt，手写页码块则 h 27pt 上下。
圈码与普通数字在「主块尺寸」上有物理可分性，在「有没有洞」上没有（两位数把洞填满）。

### 5.3 与「hole≥0.10 → 0.00」失败方案的对照——96% 不是判据失效

HANDOFF 记的失败方案：`hole≥0.10 → 0.00`，全书 184 → 350 处，「而列尾是数字的列总共 366 → 命中率 96% → 判据失效」。

本轮用现行代码复现（`VERT_RING_CRIT=v1 VERT_RING_HOLE_MIN=0`，其余不变）：

```
v1 hole>=0.10                       184 处 / 42 页   段外 0
v1 hole>=0.00（失败方案）            353 处 / 54 页   段外假阳 4 处：p424 / p484 / p495 / p1127r2
v2（本轮）                           352 处 / 50 页   段外假阳 0 处
```

关键更正：**96% 的高命中率不是判据松，而是分母本身几乎全是圈码**。
「列尾是数字的列」这个候选集在年表段里**按构造**就是圈码（年表列尾的阿拉伯数字只有圈码一种），
352/366 = 96.2% 是基率。判据的区分度要看**两个独立子集**：

- 年表段内：v1 184 → v2 352（**+168**，正是两位数圈被 hole 整类拒掉的那批）；
- 年表段外（普通数字/手写页码，14 处）：v1 0、v1+hole0 **4 处假阳**、v2 **0 处**。

也就是说：把 hole 放宽到 0 得到的是「+165 真、+4 假」；v2 得到的是「+168 真、4 个假阳**改判为 0**」。
差别在于 v2 用尺寸窗把 p424/p484/p495/p1127r2 这类**大于或小于一圈**的墨块拒了，而 hole=0 对它们无区分力。
v2 比 hole=0 还**多 3 处真圈**：v1 的 `fill<=0.78` 把 3 个填得较满的两位数圈（fill 0.80）也拒了，v2 的 0.85 容得下
（这也说明失败方案不是「放得太松」，而是「该松的没松、不该松的松了」）。
HANDOFF 的 350/57 是更早一版代码（未排除纯 0 的「〇」页码，p5/p561/p1171 等另 3 处假阳；
本轮复现 353/54 就是扣掉那 3 处「〇」后的同口径）。

### 5.4 一个反例教训：不能取「任一通过的分量」

v2 第一版按「窗口内任一连通域通过判据」实现，实测 353 处 / 段外 1 处假阳（p5「V.1」）：
主块 14.96×26.96（h 超窗），但窗口里另有 15.72×20.28 的手写碎片恰好落在尺寸窗内。
改为**只看主块**后 p5 归零，352/段外 0。这条与铁律④（参考系必须是版面格）同源：
窗口里最大的那个墨块才是「这一格的内容」，不能让一个偶然碎片代表整格。

## 11. 剩余风险

1. **圈内数字取自 OCR，两位数有系统误读**（本轮实测，非本次引入）。
   年表列尾的 `number` 直接取 OCR 文本尾数字（与 v29 同口径、也与任务E 人工条目的 21 处一致）。
   抽检 24 处中 4 处不符（17%）；按阅读序做「圈码序号非降」检查，**至少 27 处**违反（`tmp_vert/cj5/number_seq_violations.txt`），
   例：p1712 读 22 实 62、p1729 读 66/6/7 实 86/87、p1734 读 22 实约 90、p1740 读 69 实 99。
   本轮判据只解决「检不检得出」，没解决「圈里写的是几」。
   建议后续（P0-a-2）：用源图圈内墨迹做数字模板 + 年表序号单调约束，双向标定后重灌；
   在解决前，本书 >50 的 214 处里有相当一部分会画成「圈 + OCR 数字」——圈形正确、数字可能不对。
2. **>50 无 Unicode 圈码**：绘制为 `○ + 0.45F 小号数字`（v29 已有的兜底），文本层是 `○` + 两位**全角**数字
   （`○５１`，U+25CB + U+FF15 + U+FF11；tate 模式把 ASCII 数字映射成全角字形）。因此复制/搜索得到的是「５１」
   而不是 ASCII「51」，与 ≤50 的单个圈码字符（如 `㊾`）也不同。Unicode 没有 51-99 的圈码，这是标准限制；
   若要 ASCII 文本层，需把兜底数字改走 taskR2 的拉丁 TFM 字体（`ptmr8t`）或补一层 invisible ASCII 文本，
   本轮未动以保持与 v29 一致。
3. **短列圈码的竖直落位**：p1704 行13（OCR 框只有「49」两字、框高 35.8pt≈1.86 格）的圈比源图高 11.8pt
   ——渲染端对 1 字短列按**框高居中**，而源书圈在框底。这是任务S「短列」的既有口径，不是本轮引入；
   长列上的落位差 −3.4~+0.1pt。若用户对照发现该处偏高，修法在 `col_puts` 的短列 top/step 口径（会动全书版式，需单独任务）。
4. **判据的跨书可移植性**：尺寸窗 14.5-19.5 / edge≥0.20 是 wz7（步进 18.5-19.3pt、圈外径 15-19pt）实测；
   换开本/字号时需要按「圈外径/本页字步进」重标（本轮未做自动标定，窗口/阈值全部 env 可调）。
5. **段外普通数字**：本书段外候选只有 14 处手写页码；若别的书正文里有列尾阿拉伯数字（如年份、编号），
   需要补该书的反例集再定阈值——本节 §3 的方法可复用。
6. **任务E 的 36 条人工条目未重测**：本轮沿用其 number/col（bbox 匹配 21 处与普查同列同号），
   其 situation=2 的 15 条仍是人工判读结果，未做第二人复核。
