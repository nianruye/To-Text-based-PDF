## 3. 任务 A：3 个遗留

### 3.1 短列不渲染 —— 已修（残余 34 字）

- **修前**（taskO 记，用 100 页备份数据 `*.bak_taskO_100p` 复现，8 页样本 keys 60-67 = 源页 1201-1208）：
  字符量 **97.9%**；**源页 1206 两列 78 字不渲染**（「遞畢酒，林氏分付王三官…」44 字 +「小優彈唱起來…」34 字，
  实测这两列的墨迹列带在源图上**是检出的**，但「行数 18 > 槽数 16」时 DP 把一组詩行整段平移到左侧三列的
  槽位上，这两列成了「多出来的行」被静默丢弃）。
- **修后**：字符量 **98.8%**；**那两列 78 字已渲染**（`[短列补救]`/位置先验两处机制），页内越界 0。
  证据：`tmp_vert/taskP/old1200_prior0.pdf`（修前口径，缺 78 字）vs `tmp_vert/taskP/old1200_fix5.pdf`（修后，缺 34 字）。
- **残余 34 字（如实记录）**：同页另有 4 行詩句（「常將壓善欺良意，」「權作死雲带雨心？」「三官不解其中意，」「饒貼親娘還磕頭。」）
  在本轮改为不渲染 —— 该页真实列数 18、检出列带 16（两列是 2-4 字的极短列，覆盖率 < cov 0.12 检不出），
  行数 > 槽数的矛盾**必然**要丢两行；两种配平口径丢的是不同的两行（本轮取「渲染字数多者」，比修前多 44 字）。
  正解需按「无列带行 → 不参与配平、另按 OCR 列框落位」重排（本轮已实现 OCR 列框兜底，但这两行的目标列带
  被别的行占用，按「不叠字」原则跳过）。**未收**：需在配平阶段就把「无墨支撑的行」剔除出 DP（下一轮）。
- **不得把碎墨/噪点当正文**：补救渲染的**前置条件**是该位置确实有墨（run ≥ 2 条、字高中位 ∈ [0.5, 1.35] × 本页字号）；
  300 页全量跑完，`[短列补救]` 只落在 17 页、共 41 行，未出现「页边碎墨被当正文」的页（抽查产物无孤立碎字块）。

### 3.2 字号比源书略大 5-10% —— 口径问题，修后 +0.00%

| 列 | 产物 | 源书 | 相对差 |
|---|---|---|---|
| 修前口径（taskO 表的比法：产物**名义字号** vs 源书**墨高**） | 24.7pt | 22.5pt | **+10.0%**（这就是 taskO 记的「略大 5-10%」） |
| 修后口径（两侧同口径：逐页 Otsu 墨迹 run 高中位） | **22.5pt** | 22.5pt | **+0.00%**；逐页 中位 +0.00% / p10 −5.71% / p90 +2.22% / 超 ±5% 的页 31/250 |
| 源书 | — | 22.5pt 墨高（名义字号当量 26.0pt = 墨高 ÷ INK_RATIO 0.866） | |

**核查结论**：任务书假设的「源侧墨迹字高仍用固定阈值 150」在 NF 路径**已不成立** ——
`_src_ink`（标定样本）与 `page_metrics` 的 NF 分支都走 `_nf_ink`（逐页 Otsu，§1.06）。
真正的不一致在**证据表**：`final_table.py` 的产物列取 PDF span 的 `size`（名义字号），源书列取墨高，
两者不是同一个量（名义字号 = 墨高 ÷ 0.866，天然大 15%）。
本轮把两侧统一到「逐页 Otsu 墨高」后差为 **0.00%**（`tmp_vert/taskP/a2_font.py`，250 页可逐页比）。
> 附带发现：源书扫描墨高 22.5pt 对产物墨高 22.5pt 逐页吻合，说明 `INK_RATIO` 标定（0.866，探针渲染像素口径）+ NF 源侧 Otsu 的组合是自洽的。

### 3.3 页码行识别率低 —— 复核结论：(b) 判据漏（不是 OCR 数据问题）

- **OCR 侧确实提供了页码/书眉行**（逐页列在 `tmp_vert/taskP/pn_survey.json`）：300 页里 26 页有「纯数字/汉字数字 1-6 字」行
  或「金瓶梅」书眉行，例如 key 226（源页 1427）同时有 `金瓶梅`（y 425-646）与 `二五六`（y 1858-1984）两行。
- **产物侧 `[页码]`/`[书眉]` 渲染条目 = 0**（300 页全量跑完，基线与本轮都是 0）→ **不是 (a)**。
- **判别（b）的具体环节**：`special_rows` 的边带判据对这 26 页**是过的**（页码 x 676-701pt > 右带 651.4pt），
  漏在**下一步**：`special_tex` 用 `ink_extent`（源图墨迹实测）定位字号/墨迹框，该函数按 wz6 标定的
  「组件宽 3-33px / 高 4-74px / 面积 ≥ 27px² / 不贴窗边」过滤；本册页码是**小字密排 + 灰底扫描**，
  窗口内组件多落在过滤边界外 → `ink_extent` 返回 None → `special_tex` 直接 `continue`（不渲染）。
- **可选的补救（未实施，列为下一轮）**：①`ink_extent` 的组件门限按「本页字号比例」自标定（与 §1.06 逐页门限同源）；
  ②`ink_extent` 空时退回「OCR 行盒 + 页内 Otsu 墨高」定位（不依赖组件过滤，代价是 ±5pt 精度）；
  ③页码序列已拟合成功（`[页码序列] 全书 15 页有页码, value = 1.000*page + 39.0`，说明**汉字数码**页码可被解析），
  故 ② 落地后这 26 页的页码即可渲染。
