## 3. 判定

- V2/V3 在 P 不降（0pp）下 R 提升 **0pp < 3pp** → **无效/边际**。
- V2a 的 R −28pp 不是提升，且与 V2b/V2c 同配置不一致 → 属服务端/批次异常（形态同为 ASCII 逗号），不能判 maxPixels 有效。
- **结论：在现状基线 R0.8882 上，提高 maxPixels（5.6M/11.3M）无增益；正式关闭 max_pixels 方向。**
- 与 t265 撤回结论一致；V2a（TP195/FP52/FN127）与 t265 A（197/52/125）接近，说明 t265 A 很可能就是同类异常，而非 2822400 的真实性能。

## 4. 机制验证

- V1 与最优组（V1/V2众数/V3）**lines 完全相同 → 0 条差异条目**，因此没有“V1 漏、V2 补”的 20 条可裁；机制「提高分辨率救回标点」**未获得支持**。
- 对 V2a 异常组：76 行差异，均为同一位置全角 `，`→ASCII `,`（行数/字符数不变，无标点丢失），不是“像素小被抹平”；因此也不能用像素级证据支持分辨率机制。
- 裁片目录 `output/ghbq/ocr_maxpx/crops/` **为空**：无“V1 与最优组”的差异条目可裁，如实登记。

## 6. 实验规范关系

- 同窗口 V1/V3 稳定，V2 出现 1/3 异常 → 高 maxPixels 下重复性更差；后续若测其他参数，建议同窗口 2 次，异常追加第 3 次取众数；本轮已按此处理 V2。
- 与 t270 结论一致：请求确定性与时间/配置有关；不能把单次差异归因参数。
