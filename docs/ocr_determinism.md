## 3. 判定线

- 三次 lines **逐字节全同** → 本时间窗内 spotting 服务端对同 payload **确定**。
- 标点极差 0pp → 噪声可接受；但**跨时间**仍有漂移证据（见 §4），建议 A/B 规程 N=2（同窗口）+ 保留 lines hash；不必 N=3 取中位，除非两次不一致。
- 不判「当前无法做可靠参数实验」；但所有 A/B 必须同窗口、同 batch 组成、保留 raw/jobId。

## 4. batch 组成影响（8 页一次 vs 4+4）

- 整批：repeat1（8 页/job `114060245026746368`）md5 `53d35799…`。
- 拆批：batch4x2（4+4，job `114060838270455808` + `114060931159203840`）md5 **`53d35799…`**，逐页 **0 diff**，行/字符/P/R 全同。
- 结论：本样本内 **batch 组成/页面上下文不影响单页输出**。

## 5. 与历史漂移证据的关系

- t269：P0（spotting，`53d35799…`）vs 当前产品 lines **6/8 页一致，p79/p99 不一致**；同参不同时间输出不同。
- t269：L0(ocr) `b090…` vs L0b(ocr) `b9b23…`（layout 模式同 prompt 两次不同）。
- t265：A（2822400）`a6218135…` vs t268 E0（同参数）`d7c3b1b8…`。
- 本次 3 次 spotting 全同 → **非确定性不是每次请求都存在**；表现为**跨时间/模式/服务端版本漂移**。因此不能把历史 A/B 差异归因于参数，也不能依赖单次历史 baseline。

## 6. 产品影响评估

1. **同一本书当前重建两次**：同 payload 的 lines 行数/字符/md5 相同（本 8 页）；全书未重跑，但按同批行为推断为 0 文本差；若跨天/跨服务版本，可能不同（t269 p79/p99）。
2. **门禁误触发风险**：`verify_geom` 的 line_1to1 用 coords/lines 页数与行数；同 lines 不会抖动。若 OCR 漂移导致行数/字符变化，会被 `verify_geom`/`verify_typography` 的字符/行数指标捕获——这是**正确告警**，不是误触发。
3. **是否需要重建一致性检查**：建议加入「同一书同参数 OCR 重跑 lines hash 不变」作为诊断（不阻断默认构建）；跨时间差异登记为服务漂移，不能当产品回归。

## 7. 后续 OCR 实验规范（供引用）

1. **同窗口**：A/B 组在同一小时/同服务版本内连续跑；记录 jobId/raw sha。
2. **重复**：每组至少 2 次；两次 lines md5 相同 → N=2 足够；不同 → 追加第 3 次，取**众数**（非中位；标点指标不是连续量）。
3. **batch 固定**：所有组统一 8 页/批（本实验 8 vs 4+4 已证无差异；仍固定以消除变量）。
4. **显著判定**：先看 lines 级差异；标点 P/R 差值需 > 本组重复极差（本次 0pp，但按保守 2pp 作噪声底），且 P 不降 >1pp、R 提升 ≥3pp 才判可用。
5. **历史结论**：t265 max_pixels +28pp 不可复现，已撤回因果；需按本规程重做。
6. **保留证据**：每组 lines.json + jobs.json + request_payload.json；跨时间漂移单独登记，不混入 A/B。
