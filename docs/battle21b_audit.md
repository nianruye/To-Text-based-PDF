### 2.3 M1：p1229 的 insert 与源图不符（high）

**事实链（全部自测）**

1. 源图 p1229 r8 在 `何處？` 与 `清一` 之间：600dpi 裁片 + 连通域计数（多个窗口复核）→ **只有 1 个宽扁墨块**（约 16.6–18.0pt 宽 × 3.7–8.3pt 高；竖排旋转后的 `﹂`）；1600dpi 目视同结论；A（PaddleOCR-VL）该页 OCR 也是**单引号** `…在于何處？」清一…`。
2. v49 文本层该处 = `？﹂﹄清` = **2 个**闭号（`」` 和 `』`）——多出来的一个是 `data/wz7_full/wz7_full_spotting_lines_patched.json` 的符号补全层（layout 模式 OCR 补 `」`）造成的；raw spotting 文本该处只有 `？』`（1 个）。
3. v50 再插入一个 `」` → 文本层 `？﹂﹄﹂清` = **3 个**；产物在 y=584.7/601.7/619.5 画出三个独立字形（span 实测），源图只有 1 个。
4. 判据盲区：t95 的 F1「相邻闭号」只查 `」/﹂`（U+300D / U+FE42），**不查 `』/﹄`（U+300F / U+FE44）**；本处插入点左邻正是 `』`，所以 F1 没拦住。同理 fusion 阶段「B 无闭号」的窗口检查也只认 `」`。
5. `﹂﹂` 指标不敏感：本处产物是 `﹂﹄﹂`（中间夹 `﹄`），`﹂﹂` 计数抓不到 —— 237=237 正确但**不能证明**闭号没多插。
6. **角形判据本身也不可靠**：`closed_verify.json` 给 p1229 记录的 `ink = {w:18.0, h:16.6, fill:0.33}`——复算该 rect 内「按 bbox 面积最大」的连通域，实际是 **`清` 字本身**（18.0×16.6pt，y 665.3–681.9），不是引号墨块；真正的引号墨块是 18.0pt 宽 × **3.7pt** 高（y 651.9–655.6，低于判据 `4pt` 下限）。也就是说：这条候选是「拿汉字字形假阳性通过判据」的——落库证据链不成立。（其余 8 条我逐条目视+连通域确认引号墨块存在，见 §2.2。）

**该落 / 不该落**：不该落。源图该位置的闭号在文本层已经以 `』` 形式存在（且多出一个 `」`）；本 insert 是**第三个**闭号。

**建议修复（M1）**：把「相邻闭号族」扩为 `」』﹂﹄`（U+300D/300F/FE42/FE44），并增加「源图闭号墨块数 vs 产物闭号字数」的逐条比对（本可以把 23 条命中全部过一遍）。若不愿动 v50 字节，至少把 p1229 一条从 fix JSON 移除并登记。

### 3.4 明确回答：字符仲裁轮值不值得做？

**不值得按「2,379 条逐条人工仲裁」的方式做。** 理由（全部基于本抽样）：

1. **收益极小**：真错字只占 ≈5%，即全书预计只能救回 **≈118 个字符**（0.013% 于 931,193；若按保守 CI 2.4% 也只有 ≈57–240）。为这点收益要人工 + 源图逐条判 2,379 条，且 70% 的候选是 A 自己看错（源图字 = B），25% 是异体（本就不该改）。
2. **A 的仲裁精度是负的**：74% 的「A/B 差异」是 A 幻觉；ASCII/数字层 10 条中 9 条 A 错——**A 的圈号/数字读法不可信**（p1702 圈 48、p1709 圈 59、p144/p660 的 100/OOI 等）。
3. **真正的高价值子集很窄**：真错字集中在「字形相近但不同字」（蟻/螃、耽/就、刺/剌）与「大小写/数字」；这类只能靠源图判，不能靠 A。
4. **替代方案更划算**（建议下一轮）：
   - ① 异体归一并入「变体表」流程（≈25% 候选可直接自动归类、不改文本），不要开人工；
   - ② 给 **A 的数字/圈号结果加硬规则**：凡 A/B 差异涉及 ASCII 数字/圈号，一律不采纳 A；
   - ③ 若仍想救真错字，只对「A/B 都是 CJK、且两者不是变体对、且 B 是低频字」的候选（可用变体表 + 频次表自动筛）做**定向源图抽审**——预计候选 <300 条，可救回 ~100 条；
   - ④ 优先级应低于引号/括号/版面（那里有系统性缺陷，见 §2.3/§4）。
