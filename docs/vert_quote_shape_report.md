## 2. 现象与根因（用户实测 p444）

**现象**：源书诗句列尾是 `…衙。﹂` / `…鍾馗。﹂`，OCR 把 ﹂ 读成 `。` 或 `一`，渲染端照 OCR 文本画 ->
用户看到的诗句「没有闭引号」。

**根因（两层）**：
1. OCR 误识：﹂ 是 19.5×9.5pt 的直角细笔画，被识别成句号（同尺寸圆环）或汉字「一」。
2. 为什么必须在渲染端做：外部工具拿不到「只含一个字形」的图（v1/v2/v3 三轮全败，见简报 §2）；
   渲染端 `col_puts` 本来就算出了每个字画在哪一格。

**本轮新增的实测发现（与简报假设的差异）**：
- 槽格 x 带**有整列偏移**：p444 列墨迹 x519-543 被排进槽 529-555（+11pt）。按槽带裁会把 ﹂ 的竖臂切掉，
  四角特征退化成一条横线 -> `bar`。故取样先按「离槽中心最近的墨迹 x-run」认列。
- 槽底 `bot` 来自 dink（深墨）run，**漏掉淡墨引号**：p444 列 a 的 bot=797（句号环底），
  ﹂ 在 814.5-824.0（槽底之下 0.7 步进）。故取样 y 窗向下外扩 1.3 步进。
- 诗句列是**上下半句合并列**（OCR 两行 y 间隔 ≤2.5 步进），渲染步进按合并字数均分，
  列尾渲染格位比源墨高 1-2 格；引号必须按源图尾 run 取样，不能只看渲染格位。
- 双字形态：p444 列 a 的源书是 `…衙。﹂` 两个字形，OCR 只给了句号（`…衙。`），引号整格丢失 ->
  **append**（保留句号，补 ﹂）而不是替换；列 b 的源书 `…鍾馗。﹂`，OCR 给的是 `…鍾馗。一` ->
  **replace**（「一」就是引号格）。
