## 现象 2：书眉与页码被当成同一列（p86）

构建日志：

```
[正文列] p86 19 行 -> 18 槽 (槽 run [5, 46, 42, 17, 16, 43, ...])
                              ↑ 槽 0 的 run 数 = 5
```

源页 86 的两条 OCR 行：

```
金瓶梅   bbox x1655-1708px  y634-890px     （3 字，字距 42.7pt）
四二     bbox x1655-1708px  y2363-2467px   （页码，2 字）
```

**两者 x 完全相同 → 落进同一个 x 槽 → 槽 0 的 run = 3+2 = 5。**

渲染结果：

```
金 y=295.1   瓶 y=320.6   梅 y=448.0
                 步进25.5        步进127.4  ← 正常应 25.5
```

「梅」被排到第 **7** 格（应为第 3 格），**偏 127.4pt**。
且**页码「四二」整个丢失**（19 行只有 18 槽，多出的行被 DP skip）。

## 现象 3（同类）：页码混入正文列

p513 产物第 1 列 = `﹁四六常九言富者貴之基，` —— 页码「四六」被塞进了诗句列。

## 三、根因（已定位，供你确认而非重找）

1. **`_align_rows_slots()`（约 L2696）** 按「格数/run 数 + 位置先验」做 DP 配对，**不知道某行是书眉/页码还是正文，也不知道两行 y 相距多远**。
2. **槽是纯 x 带**（`_ink_bands`），**槽内 y 方向的大空隙没有拆开** —— 书眉(y317-445) 与页码(y1181-1233) 之间 **736pt 空白仍在同一个槽里**。
3. 因此一个槽对应两条 OCR 行时，DP 只能留一条（另一条 skip → 丢页码）；留下的那条按**整个槽的墨迹范围**算步进/空隙 → 步进与空隙判断全错。

---

## 四、修法方向（建议，不强制）

**方案 A（推荐，解决结构性问题）**：**槽按 y 拆子槽**。
在每个槽内对墨迹做 y 投影，若存在 **> 2.5 × 字步进** 的连续空白 → 拆成多个子槽。书眉 / 页码 / 正文自然分开，行↔槽恢复 1:1。

**方案 B（兜底）**：`_align_rows_slots` 增加硬约束 —— 行与槽的 **y 范围必须重叠**（不重叠则禁止配对），代价里加 y 中心距离项。

**方案 C（可选）**：配对前把明显的书眉/页码行单独分离，走已有的书眉渲染路径（§1.0，L900-945）。

建议 **A + B 组合**：A 解决结构性错配，B 兜住残余。

✅ **正确口径**：把产物 **逐字 span 按 x 聚成列**（容差 = 半列距），再与 OCR 行 **按阅读序并排逐列对照**，比 x 与列序。
现成脚本：`/tmp/cols_side.py`（上游写的，直接可用，改页号即可）。

❌ **不要用下面任何一种口径**（上游已全部踩过，会得出假结论）：

| 错法 | 造成的假结论 |
|---|---|
| `round(span_x/12)` 分桶数"独立列" | 虚报 6,699 次"标点伪列" |
| 产物墨迹 run 数直接 vs OCR 字数 | 汉字多笔画（三、二、川）一字多 run → 虚报 1,257 列异常 |

| 1-based / 0-based 混用 | `fax_pages.json` 的 `pages` 是 **1-based**；PDF 页索引 **0-based** |
