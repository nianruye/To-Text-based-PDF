### 1.2 y 拒绝 0/554 不是字段缺失，也不说明配对正确

槽确实带 `top/bot`（`_slots_of_edges` 生成，`_align_rows_slots._geom_ok` 里也有 y 分支）。
拒绝 0 的真正的结构性原因：

- NF 正文槽是**整列高的竖条**（p159 实测 10 个槽的 `top/bot` 覆盖 212–1331pt 的正文带），
  相邻槽在 y 上完全重叠；
- 「整列错开整数列」是**水平方向**的错配。行与它被配到的槽在 y 上当然相交，
  y 约束对水平错位没有任何分辨力。

因此质疑的选项 **(b) 成立：行确实与所配槽 y 相交**；p159 的 −86pt 另有原因（见 §2/§3），
不是 y 判据能拦的东西。能区分左右的是 `_geom_ok` 的 **x 中心距**约束；而它只在
`geom=True`（`_ab` 页）时启用，且门限 `AB_XK=2.0×列距` 恰好放过了 p159 的 1.98 列偏移
（详见 §2.3）。`/tmp/nonfixed_build.log` 的 45 页是**未标定页**（`fixed=False`），
`_ab=False` ⇒ 连 x 约束都没有，y 探针本身只是在模拟一个不存在的约束。

结论：A 档（只加 y 相交约束）对水平错列**必然无效**，这一点维持原判；但原因不是探针错，
而是「y 约束与错列方向正交」。

## 3. 根因结论

### 3.1 机制：`nf_edges` 用「相邻检测带心中点」当槽边界，槽心被空隙拉偏

`nf_edges`（build_vert.py:2344）原文：

```python
"""... 边界 = 相邻带心中点, 首末外扩 pitch/2; ..."""
cs = sorted((a + b) / 2.0 for a, b in bands)
p  = statistics.median(ds)
return [cs[0] - p / 2.0] + [(a + b) / 2.0 for a, b in zip(cs, cs[1:])] + [cs[-1] + p / 2.0], p
```

槽 i 的边界 = `[(c_{i-1}+c_i)/2, (c_i+c_{i+1})/2]`，其中心相对本列墨迹中心 `c_i` 的偏差为：

```
shift = ((c_L + c_i)/2 + (c_i + c_R)/2)/2 - c_i
      = (c_L + 2c_i + c_R)/4 - c_i
      = ((c_R - c_i) - (c_i - c_L))/4
      = (G_R - G_L) / 4                    # G_L = c_i-c_L, G_R = c_R-c_i
```

也就是：**左右相邻列带距离之差 ÷ 4**。正常页相邻列距都在 p 附近，`G_L≈G_R≈p` -> shift≈0。
但只要本列某一侧是**空白**（章末、段末、正文块边界、页边书眉/页码列），该侧 `G` 就会变成
数倍 p，槽心便整体偏 (G-p)/4。

p159 的实测代入：

```
G_L = 507.75 - 110.75 = 397.0 = 8.87p   （左侧 8 个正文格全空 + 页左书眉/页码列）
G_R = 550.25 - 507.75 =  42.5 = 0.95p
shift = (42.5 - 397.0)/4 = -88.6pt = -1.98p
```

产物把这一列画在 `xc=419.1`，而真列在 507.75 —— 就是用户量到的 −86.4pt。
`col_puts` 里所有横向量都从 `sl['x0']`/槽宽派生（正文 `x_put=xc-XSCALE*F/2`，
标点 `tx=sl['x0']+PUNCT_DX*pitch`），所以整列（含标点）一起平移。

### 3.2 为什么是「整数列」以及为什么章末套语几乎都是 −2.1 列

- 偏差本身是连续的 `(G_R-G_L)/4`，不是量化到整数格。
- 但**章末页的结构是固定的**：套语列（「畢竟未知後來何如，且聽下回分解：」这类）是本章最后一列，
  它左侧的正文格全是空白，直到页左的书眉/页码列才重新有墨。wz7 的页左书眉/页码列与正文块
  相隔约 **8-9 个列距**（p159：8.87p），于是
  `shift ≈ (p - 8.87p)/4 = -1.97p ≈ -2 列`。
  27 条章末套语几乎全是 −2.1 列，正是因为这 27 页的「套语列 -> 页左书眉列」的空白宽度相同
  （同一版式、同一章末位置）。
- p149 的诗句是 +2.2 列：那一列的大空隙在**右侧**（`G_R` 大、`G_L≈p`），符号相反、量级相同。
- 其余普通正文列两侧都有邻列，`|G_R-G_L|` 只有几 pt，槽心与带心几乎重合；用户表里
  +3~4pt 是「产物字形墨迹左缘 vs 源图墨迹左缘」的固定字形差（同一字号下的度量口径差），
  不属于本 bug。

### 3.3 与配对、geom、y 约束的关系（回答 §1 的疑问）

- **配对是对的**：`row8 -> slot2` 语义上正确（该槽的 x 范围确实包含真列 497.5-518.0）。
  所以「y 相交约束拒绝 0」不是漏检 —— 行与槽在 y 上真的相交，问题在 x 方向的**槽几何**。
- `_geom_ok` 的 x 约束本可拦下：`|Δx| = 1.979p`，但 `AB_XK=2.0p`，**差 0.021p（0.94pt）没拦住**。
  即便拦住，DP 也只能跳过该行/该槽，行会落到 `_nf_rescue_rows`；而残余列判据按「已用槽的 x 带」
  扣墨（日志：已用列带包含 `498-518`），真列会被判成「已用」，该行反而可能丢字。
  所以**不能靠收窄 AB_XK 修**（见 §4）。
- 未标定页（`fixed=False`）连 geom 都不开，纯格数 DP 更不可能发现这种偏移；但偏移在
  槽建成时就已存在，与配对口径无关。
- 这也解释了为什么全书 434 列 / 236 页都有：**每一列只要一侧邻列是空白，就会被拉偏**；
  与是否标定、是否走 `_ab`、行数是否等于槽数都无关。

### 3.4 证据闭环（三条独立证据）

1. **数值闭环**：`(309.25+529.0)/2 = 419.125`；`419.125 - 507.75 = -88.6`；
   产物 tex 该列 16 字全在 x=412.6，反解回页坐标即 `xc=419.125`（§2.4）。
2. **对照闭环**：同一页左侧两行（书眉 + 页码）走的是 `_nf_rescue_rows`，按**残余墨迹列中心**
   （98.3-118.3 -> 108.3）渲染，产物 x=97.1 vs 源 94.0（+3.1），**没有 −86pt 现象** ——
   走墨迹带中心的路是对的，走槽中点的路是错的。
3. **符号闭环**：偏差公式 `(G_R-G_L)/4` 同时解释 −2.1（章末，空隙在左）与 +2.2（p149 诗，空隙在右）。

### 3.5 结论一句话

**根因 = `nf_edges` 把槽边界放在「相邻检测列带中心的中点」，槽心因此被一侧的大空白拉偏
`(G_R-G_L)/4`；渲染又完全以槽心为列位。配对、y 约束、geom 都是无辜的。**
修法应作用于「槽的 x 窗口/中心」，而不是配对或 y 判据。

## 4. 修法方案（A/B/C 重估，我原来的 A 档已作废）

| 档 | 内容 | 判定 |
|---|---|---|
| A | 配对加 y 相交约束 | **作废**（已验证 0 拒绝；错列是 x 方向，y 与它正交） |
| A' | 收窄 `AB_XK`（2.0 -> 1.5） | **不采用**。p159 的 x 距离 1.979p 会被拒，但 DP 只能跳过该行/槽；`_nf_rescue_rows` 按「已用槽 x 带」扣墨，真列 497.5-518 已被槽 2 占用 -> 行无处可落，反而丢字 |
| **B** | **槽窗口锚定到本列墨迹带中心** | **推荐**（见 4.1） |
| C | `nf_edges` 改成正列距栅格 + 空隙处插双边界 | 更「物理正确」，但会改变槽数/槽序（多出空槽），牵动 `AB_ALLSLOTS` 配对/特殊行/目录分支；不建议首修 |

### 4.1 B 档实现（最小改动，NF 路径专属）

1. `_nf_frame` 返回时把**最终** `bands`（已含 `nf_fill_bands` 补齐 + `nf_short_bands`
   短列）按带心排序后放进 g：`'bands': sorted(bands, key=lambda b: b[0]+b[1])`。
2. `_slots_of_edges(..., anchors=None, pitch=0.0)` 增加两个可选参数；逐槽：
   ```python
   c = (anchors[i][0] + anchors[i][1]) / 2.0
   mid, w = (e0 + e1) / 2.0, e1 - e0
   if anchors is not None and pitch > 0 and w > 1.25 * pitch and abs(mid - c) > 0.15 * pitch:
       # 病态槽（被邻侧大空白拉宽/拉偏）：窗口以本列带心为中心，宽度回到一个列距
       e0 = min(c - pitch / 2.0, anchors[i][0] - 4.0)
       e1 = max(c + pitch / 2.0, anchors[i][1] + 4.0)
   ```
   - 阈值 `w > 1.25p and |Δmid| > 0.15p`：正常槽的局部列距波动约 ±10%（`|Δmid| ≤ 0.05p`），
     **逐位不变**；两侧差 2 列以上的槽（`|Δmid| ≥ 0.25p`）会改。p159 的槽 2 是
     `w=4.91p / |Δmid|=1.98p`，远在阈值外。
   - `_slot_runs` 的 3.5pt 内缩已计入（窗口边缘比带缘再留 4pt），不会切掉本列墨。
   - 槽的数量/顺序不变 -> `_align_rows_slots` 的配对结果不变；只改 `x0/x1`（进而改
     `col_puts` 的 `xc` 与标点的 `sl['x0']+PUNCT_DX*pitch`）。

**已知副作用（验收时必须逐页看）**：槽 1（页左书眉/页码列）回中后，p159 的两行

## 5. 验收方案

1. **单测（纯函数）**：合成 bands `[110.75, 507.75, 550.25, 596.5, ...]`、p=44.75，
   断言槽 2 窗口 = 485.4±、槽心 = 507.75；普通槽 x0/x1 与修前**逐位相同**；
   带缘保护（band 宽 > pitch 时窗口不小于带宽 + 8pt）。
2. **p159 单页**：重跑 `VERT_PAGES=159`；断言 tex 里「畢竟未知…」16 字的 x 从 412.6
   变为 ~502.8；10 个正文列位与源墨迹带心差 < 0.25p。
3. **全书量化**：用用户那套「源图墨迹列带 vs 产物列位」测量重跑 300 页样本（或全书），
   统计 `|Δ| > 0.5p` 的列数：目标从 434 -> 0（或仅剩无法归因的特殊行）。
4. **verify_vert（300 页样本）**：必须保持 PASS（页数 1:1 / 字符量不低于基线 98.2% /
   整页丢失 0 / 越界 span 0 + 矢量 0 / 页幅 0.01%）。本修法只改 x，字符量应逐页不变。
5. **wz6 零回归**：有版框路径不经过 `nf_edges`；`vert.tex` md5 必须与基线相同 + verify PASS。
6. **401 测试全绿**；新增单测锁住「正常槽逐位不变 + 病态槽回中」。
7. **回归观察项**：由于窗口变窄，个别槽的 `nr/hm` 可能微变 -> 对比 300 页逐页
   `m['body']/m['note']` 槽集合是否变化；若变化，逐页说明（预期为 0，因为窗口只从
   空白区收窄到本带 + 4pt，原窗口内的墨本来就只有本带）。
