## A. 标点挤格（含 ①字重叠根因）

**源书实测**（探针 `tmp_vert/ascii_ink.py` / `col_gaps.py`，wz6 p10 逐字墨迹反推）：
句号/逗号**挤在前一字格右下区**，其墨心 = 前字格顶 + **0.85 格**（，0.84 / ？1.15，取 0.85）、
x = 格左缘 + **0.81×格距**（格距 43.4pt）；**下一字仍在「前字格顶 + 1 格」→ 标点不占格**。
证据：p10 列「黨之間加緊磨擦一下，把對外的眼光轉到對內。這種情況差不」27 字（含 2 标点）= **25 格**，
格步进 62px(2x)=31pt ≈ 字号（34.4pt 的墨高 30.3pt）——旧实现按 27 字排格 → 28 字列步进被压到 28.5pt < 30.3pt = **字粘连（用户①）**。

**实现**（`build_vert.py` §1.0 + `col_puts`）：
- `n_cells(t)` = 字数 − 挤格标点数（`。，、；：？！` 及竖排变体 `︒︑`；引号/括号仍占整格 —— 源书亦然）；
  列对齐 DP 代价同步改格数口径；OCR 半角 `,.:;!?` 在前字为 CJK 时归一化回中文标点（实测 key47「的努力,更加造成」等）。
- 标点单独字号 `PUNCT_SIZE=0.62×F`（源书标点墨迹高约正文的 0.17em，本项目 Noto 标点 0.27em，按 0.62 缩放后一致），
  用字形墨心相对 `\put` 锚点的实测偏移（探针 `tmp_vert/probe_punct_tex2.py`，F=34.4pt）反解锚点，落到上述源书位置。
- 列顶/列底仍贴本槽实测墨迹（§1.98 原逻辑不动）；标点不参与列高。

**量化**（`tmp_vert/check_pitch_tex.py` 解析 vert.tex）：
正文列 57674 相邻字对，步进 < 墨高 34 对（0.06%）；步进/墨高 比率 p1 1.049 / 中位 1.058；
旧口径（标点占格）解析重算 = 253/62669（0.40%）。p10 首列修复后步进 30.9pt ≥ 墨高 29.7pt。

## B. 字号保护

`col_puts` 加护栏：**墨高 = 0.88×字号 ≤ 0.95×步进**，越则本列缩字号并按新墨高重算步进（最多 3 轮）。
口径说明：任务书写「字号 ≤ 步进×0.95」，本项目的 `m['font']` 是 **em 字号**（墨高/0.88），
源书自身墨高/步进实测 0.93–0.95 即处于该上限（真实排印不会让 em ≤ 步进），故按「墨高 ≤ 0.95×步进」实现，
等效于「字号 ≤ 1.079×步进」；正常列不触发，只兜住 OCR 字数异常（多字）的列。

## C. 『』等符号缺失（数据层）

**参数实验**（p9，客户端 `src/ocr/run_spotting_ocr.py` 同源请求，原始响应落盘 `tmp_vert/ocr_exp/`）：

| 组 | 参数 | 符号保留 | 行级坐标 |
|---|---|---|---|
| A | layout=F + promptLabel='spotting'（现行） | 『=0（连标点都丢） | **有**（13 条 rec_polys） |
| B | layout=T | **『2 』2 ；1 ，13 。4 、2 ？7（与源书一致）** | 无（整页 1 块） |
| C/D | layout=F + 'ocr' / 无 promptLabel | 『』在，其余标点全丢 | 无（1 块） |
| E | promptLabel='text' | API 422 拒绝 | — |

→ **无单组参数兼得**；且为页特异不稳定（p10 的 spotting 完整保留（五）（六）与全部标点）。
**做法**：`src/tools/patch_vert_symbols.py` —— 用 layout 模式全书 OCR（`data/wz6/wz6_layout_*.json`）
的 `vertical_text` 块按阅读序拼串，与 spotting 正文行按阅读序拼串做 `difflib` 模糊对齐，
只把 **layout 有而 spotting 无的「符号集」字符**（引号/括号）插回对应行；**几何数据一律不动**，
也不采纳 layout 的其它差异（layout 自身的句读标点也有丢失）。

## D. p3 越框

**回退判据为何漏过这页**：`page_metrics` 的正文/注槽分类用「槽墨迹高度 ≥ 0.75×全页最大」——
p3 是**章题页**，标题列（42pt）把 `hmax` 抬到 84px，正文列（31pt）被判成注槽 → 12 槽里只剩 2 个
"正文槽" → 9 行 vs 2 槽「不适配」→ 回退 v2 流式排版。而流式排版的列位/字号取自 OCR 盒
（y 向伸缩 ~10%）、列从「版心右缘(563.1)」起排且列高不受内框约束 → 列底越版框 50–90pt，
右起首列字号大时还越右框 12.5pt（= 用户报的 4 处 span）。

**修复**：新增 `page_puts_loose`（`build_vert.py` §1.99）：对「有版框但无槽可配」的页（p3/p156/p199/p210/p229），
不回流式，改用**内框内墨迹列带绝对定位**：
① x 取源图墨迹列带（cov 0.12，按阅读序 + run 数 DP 与行配对），配对不上的行再用「残余墨迹列」补位
（大字距章题列 x 向覆盖度仅 0.05，列带检测抓不到 → 用已配列带覆盖后的残余墨迹找），再兜底「未用等分槽位」；
② 字号 = 带内墨迹字高中位/墨比（**不能按步进反推**：章题「論 持 久 戰」步进 100pt 是字号 45pt 的 2 倍），
并用「带宽容得下的字号」与「页级字号中位×1.35」双重上限兜住粘连长 run（曾把字高测成整列高）；
③ 列顶/列底 = 带内自然跨度（夹进内框），标点挤格/字号保护与正路同。

**结果**：p3 水平越内框 span **0**（修前 24 个 / 最深 86.8pt）；p199/p229 亦 0；
p156/p210 残留 8/10 个是**书眉·页码在版心外**（源书自身位置，`special_tex` 按源墨迹定位）；p3 与源书整页对照
（`tmp_vert/cmp_p3_loose.png`）列序/标题字距/正文列位一致。
