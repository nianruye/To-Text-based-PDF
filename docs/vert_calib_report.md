## 1. 审计回顾（为什么必须改）

任务书审计表的结论：机制大多通用（列位/列距/版框/页码序列/derot 全部取自源图实测），但下面这批值是
**这本书的**：

| 常数 | 原值 | 为什么换书必然失准 |
|---|---|---|
| `N_COL_FRAME` | 12 | 被用来反推版框内框左右缘（`frame_geom`）与槽格分母 → **列数错则整页列位错** |
| `XSCALE` | 0.87 | 「源书铅字比候选字体窄 1.48 倍」是 wz6 的窄长体特征 |
| `PUNCT_SIZE/DX/DY`、`GAP_HANG` | 0.62 / 0.81 / 0.85 / 0.85 | 挤格标点的大小与摆位按 wz6 源图统计 |
| `BR_SIZE_DEF`、`BR_SIZE{︗︘︹︺}` | 0.66 / 0.55 / 0.49 | 括号字号按 wz6 源图实测 |
| `INK_RATIO/INK_ASC/NOTE_INK_RATIO/NOTE_INK_MAX/VERT_METRICS/PUNCT_INK` | 0.88/0.94/0.88/0.94/14 项/7 项 | **字体绑定**（按 Noto Serif CJK TC 标定）——换字体就得重标 |
| `V_FRAME_GAP/TH` | 3.2/3.4pt | 缺测补位值（实测优先）→ 标注为兜底 |
| `NOTE_STEP_RATIO` | 0.85 | 判据性上限 → 复核 + env 可调 |

## 2. 实现

### 2.1 标定趟（两段，都在建排前跑一次）

- **趟 A `L1080-1144`（必须早于 §1.96 右缘复测）**：抽样 16 页，逐页算
  ①内框宽÷列距（取整）②界行线条数-1 ③实测最外两条细线跨距÷列距；取「①=③ 一致页」的众数（两条独立口径互证），
  无一致页退 ②，都不可测回落 12。
- **趟 B `L2023-2696`**：
  (a) `kpsewhich` 解析 `VERT_FONT` → fontTools（`.ttc` 取名字含 TC 的面）算 `VERT_METRICS`/`PUNCT_INK`/`NOTE_INK_MAX`；
  (b) 源图侧：复用 §1.98 的槽/行配对，逐字取「单体字」墨迹（高/宽/面积）与小字连通域（标点/括号）；
  (c) 探针：**用主 preamble 真编译** 2 页。每字隔离 `\put`，2x 灰度 <150 测墨迹 —— 这是「字号↔墨高」换算
  必须落在**像素口径**上的原因（轮廓口径系统性偏高 4.5%，会让全书字号偏小）；
  (d) 组合出各参数；(e) `VERT_CALIB_CACHE` 可跳过 (b)-(d)；(f) 清 `_metrics_cache` → 应用生效值 → 打印对账表 → 落盘 JSON。

### 2.2 关键口径（详见 spec §4）

| 参数 | 口径 |
|---|---|
| `XSCALE` | **单字「墨面积/墨高²」**（源书中位 ÷ 渲染中位）。x 向压缩 K 不改墨高、把面积乘 K，故该比值就是 K |
| `PUNCT_SIZE` | (源标点墨高/正文字高) × (渲染正文字高em ÷ 渲染标点墨高em) |
| `PUNCT_DY/DX`、`GAP_HANG` | 源标点墨心（或墨顶）相对**前字格顶 / 槽左缘**的偏移，单位 = 步进/格距（与 `col_puts`/`fit_gaps` 同一坐标语义） |
| `BR_SIZE` | `sqrt(s_h×s_w)`：`s_h` 只对高、`s_w` 对宽（含 `XSCALE` 还原）—— 即 taskK 当初「宽高同时最接近」的定法 |

**源侧两个必须记的坑**（都实测踩过）：

1. **槽窗口要内缩 3.5pt**：槽两侧就是界行线，不内缩会把 1-2pt 宽的线算进「字墨迹」→ 墨宽测成槽宽、面积虚高 30%。
2. **小字要用二维连通域，不能用槽的 y 投影**：挤格标点的 y 区间落在前字的墨迹区间内（实测 p15「問：」：
   标点墨迹 x552-554/y357-364 被「問」的 y 投影吞掉）→ 投影法永远配不上标点，DP 会把下一个字的小笔画当标点
   （首轮实测 `PUNCT_SIZE=1.41`、`PUNCT_DX=0.54`，全是错配出来的）。

### 3.2 `BR_SIZE_DEF` +15.6%：是口径差，不是标定错

- **现值 0.66 的口径**（见 `build_vert.py` §1.0c 注释）：源书墨迹 17.5×7.0pt ÷ **渲染端轮廓几何** 0.936×0.286em →
  `s_h=0.711 / s_w=0.636` → 折中 **0.667**。
- **本次标定的口径**：源书墨迹（**像素**） ÷ 探针**渲染像素** 0.884×0.268em → `s_h=0.842 / s_w=0.709` → 折中 **0.773**。
- 差异来源可量化：同一字形在「轮廓 vs 2x灰度<150 像素」两种测量下，墨高差 **6%**（0.286→0.268em），墨宽差 **5.6%**
  （0.936→0.884em）—— 小字号细笔画被二值化吃掉边缘。**源书侧两种口径一致**（本次 0.259 高比 vs 注释里的
  0.23-0.24，实测括号墨高 7.0-7.6pt）。
- 哪个更接近「看起来一样」？把两者分别代回渲染式（`F = 源墨高/INK_RATIO`，含 `XSCALE`）：源书 ︵ 是 17.5×7.0pt，
  0.66 给 17.0×6.0pt（**高 -14%**），0.763 给 19.3×6.9pt（**高 -1.4%**，宽 +10%）—— 最大相对误差从 14% 降到 10%，
  且**高度对上了**（高度是「看起来像不像」的主项）。
- 产物侧独立对照（抽样 14 页，源书与两个产物的「扁长条标记」按墨心配对）：产物墨高/源书墨高 中位
  **标定前 0.824 → 标定后 0.862**（更接近 1）。
- 想保留旧观感：`VERT_BR_SIZE=0.66 VERT_BR_SIZE_MAP='︗:0.55,︘:0.55,︹:0.49,︺:0.49'`（env 优先，见 §7）。

> 【】〔〕（black/lent）样本只有 2-3 个（全书仅出现 8-19 次，分布在 p156/157/158/191/192/199/227-230），
> 按小样本估计量取**最大值**（漏检只会把标记测小）。标定值 0.740/0.763 比原硬编码 0.55/0.49 大：
> 源书实测这两个字形是 20.7×7.8pt / 18.1×6.8pt，按 0.55 渲染只有 15.0×6.5pt —— **原值偏小**。

### 3.3 `GAP_HANG` -12.7%：同源统计的两种口径

`PUNCT_DY`（墨心）与 `GAP_HANG`（墨顶）是**同一次源图统计**的两个投影，物理上必然差
`标点墨高/2 ÷ 步进 ≈ 0.10 格`：0.840（墨心） − 0.742（墨顶） = 0.098 ✅ 与实际标点墨高（0.2 格）一致。
当初这两个值都被写成 0.85（同一口径），即 `GAP_HANG` 一直是**墨心口径**的值。
本次按代码注释的字面语义（`fit_gaps` 里 `hratio` 用于预测**墨顶**）取墨顶口径 → 0.742。
**产物无影响**：`fit_gaps` 的 `m`/`e` 转移都要求「非挤格标点」，`hratio` 实际只进调试打印
（空隙检出清单标定前后都是 75 处/90 格/58 页，逐字节相同）。

## 6. 换成另一本竖排书，现在还需要人工改哪些常数？

**能自动的（本轮改造后，无需人工）**：列数、字宽压缩、标点字号/摆位、括号分档字号、字体绑定组
（墨高比/墨比上界/竖排形态墨心/标点锚点）、列高/列距/列位数/天头/版心右缘/版框线/界行线/页码序列/旋转页/
边注与书眉页码定位 —— 全部由源图与字体文件测出。

**仍需人工（或下一步要做的）**：

| # | 项 | 现状 | 建议 |
|---|---|---|---|
| 1 | **字体选择**（`VERT_FONT`/`VERT_GFONT`） | 默认 Noto Serif CJK TC 写死；taskL 的结论是 wz6 用宋明体系最优，但**没有自动字体识别** | 换书时人工按源书字形选字体（或接入已有的字体识别流程）；选定后所有字体绑定常数自动重标 ✅ |
| 2 | **书眉/页码的页边带 px 常量**：`is_body_col` L425（`x0>1100` 判定书眉页码、`x0<100` 判定左边注、`h/L<55`、`h<300`）、`special_rows` L497（`h>=300`/`x0>1100`/`x1<100`/2≤字数≤10）、`note_rows` L607（`x0<100`） | **2x px 绝对量**（1100px = 550pt），只对 wz6 的页幅（595×1245pt）成立 | 改成页宽/内框的比例（1100/1191 = 0.924、100/1191 = 0.084），或按内框左右缘的偏移量定义 |
| 3 | **版框几何合法性区间**：`frame_geom` 内框高 `700 ≤ h ≤ 900pt`（L929）、内框宽 `400 ≤ w ≤ 640pt`（L1008）、横线判据「跨度 > 0.55 纸宽」、`_grid_fit` 的列距枚举 `40.0-48.0pt`（L841-846）与跨度 `400-640pt` | 与 wz6 的开本/栏格绑定 | 改成「相对页高/页宽的区间」（如内框高 ∈ 0.5-0.75 页高）与「列距 = 内框宽/列数 附近 ±15%」 |
| 4 | **版框线粗细判据** `V_THICK_MIN=2.4 / V_THICK_MAX=6.5`（pt）、`V_FRAME_GAP=3.2 / V_FRAME_TH=3.4`（兜底） | 源书外框 2.5-4.5pt；别的书若外框更粗/更细会漏检或误检 | 已有 env（`VERT_FRAME_TH/GAP`）；更彻底做法 = 从实测线宽分布聚类 |
| 5 | **页边小字组件尺寸窗** `ink_extent`（宽 4-40px、高 5-90px、面积 ≥40px）与 `note_cols` 的 `0.25-2.2×步进` | 按书眉/页码/边注的字号量级设的 | 改成「0.2-1.2 × 该行墨高」这类相对量 |
| 6 | **`NOTE_STEP_RATIO=0.85`**（边注/正文步进比上限，判据） | wz6 实测比 0.69（余量 18%），未见过紧 | 已加 env `VERT_NOTE_STEP_RATIO`；若新书注/正文比更高（>0.85），需调大 |

**判据类常数（不按书标定，通用但需留意）**：`V_LINE_COV 0.55 / V_LINE_COV_LO 0.30 / V_H_COV 0.45`（扫描淡墨质量）、
`_bar_px` 0.80（扫描黑边）、`DEROT_*`（旋转页判据）、`GAP_MAX=4` 与 DP 代价（空隙检测）、`PN_TOL/PN_GAP`（页码序列）、
`page_rows` 的步进间隙比 1.18（正文/注分离）、`page_metrics` 的 `0.75×hmax`（正文/注槽）与字号 10-60pt 区间、
`col_puts` 的 0.75-1.30×步进夹取、字号保护 0.95×步进 —— 这些是**算法权重/判据**（尺度无关），换书风险低。

## 7. 失败项 / 局限（如实）

1. **`BR_SIZE_DEF` 与原常数差 +15.6%**：原因是口径（§3.2），不是标定错误；产物上括号会比之前大 10-15%
   （高度更贴源书）。若要回到旧观感：`VERT_BR_SIZE=0.66 VERT_BR_SIZE_MAP='︗:0.55,︘:0.55,︹:0.49,︺:0.49'`。
2. **`dbl`（《》）与 `ang`（〈〉）两族在 wz6 上 0 样本**（全书各 8-9 次，且抽样页里没配上）→ 回落 `BR_SIZE_DEF`。
   日志逐族列出无样本的族；`VERT_BR_SIZE_MAP` 可手工指定。
3. **`lent/black` 只要到 2-3 个样本**（全书 8-19 次）→ 用「小样本取最大值」估计，**置信度低**，日志标出样本数。
4. **`GAP_HANG` 当前不影响产物**（DP 里该参数只进调试打印，见 §3.3）—— 标定值是「按语义取的正确口径值」，
   将来若把挤格标点接入匹配转移，值就已经是对的。
5. **标点摆位只标定了「位置」，没有标定「点画形状」**：源书标点是印刷铅字点，字形与 Noto 不同（用同一 `PUNCT_INK` 口径对齐墨心）。
6. **括号在格内的偏移未标定**：`_br_put` 一律把墨心摆回格心；实测源书 【】 的墨心在格上下缘（d_cy 0.19/0.81）而非 0.5 →
   属「位置」类遗留（本轮只按规格标定字号）。
7. **扫描件墨迹口径**：源侧测量对阈值敏感（本报告全部用 2x 灰度 <150；`page_metrics` 内部另用 <110 深墨测列顶列底）。
   极淡/极重的扫描件可能需要调 `V_LINE_COV*`（见 §6 判据类）。

## 8. 修复过程记录（标定趟引入的两个复现性缺陷）

1. **`_metrics_cache` 污染**：标定趟抽样时会先调用 `page_metrics(pi)` 并把结果缓存，而那里面的字号是用
   **标定前** 的 `INK_RATIO` 算的 → 被抽样的页会用旧字号渲染（实测 p192 字号 22.2 vs 22.4）。修法：应用标定值后
   `_metrics_cache.clear()`（`L2667`）。
2. **稀有括号补抽顺序不确定**：`_need` 是 set，只按样本数排序 → 相同样本数时顺序随 `PYTHONHASHSEED` 变，
   两次构建抽到不同的补抽页（实测 `vert.tex` 差 1020 行）。修法：排序键加族名（`L2531`）。
   修后两次构建（不同 hash seed）逐字节相同 ✅。
