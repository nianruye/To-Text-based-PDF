## 二、必须遵守的构建/验证口径（踩过坑的硬约束）

### 2.1 三套入口，argv 顺序各不相同（极易传反）

```bash
# 竖排构建（注意 LINES 在前！）
build_vert.py  LINES  COORDS  OUT  SRC

# 竖排验证（coords 在前，与上面相反！）
verify_vert.py <out.pdf>  COORDS  LINES  --src-pdf <src>  --expect-low <页列表>

# 完整管线（含 fix_tounicode_circled 后处理）
src/pipelines/rebuild_v6.sh
```

**传反的报错不是「参数错」**，而是 `TypeError: unhashable type: 'list'`
（`sl` 里装进坐标多边形 → `fix_split_brackets` 的 `t[0] in BR_OPEN_OF` 炸）。
快速自查：`python3 -c "import json;d=json.load(open(SL));print(type(d['0'][0]))"` → 打印 `str` 才对。

### 2.2 对账基线必须用默认 env

`rebuild_v6.sh` 里写死了 `VERT_BOLD=0.5 VERT_TOC_RESCUE_OK=1`，会改变
`INK_RATIO`（0.866→0.872）→ 与默认 env 的基线不可比（曾差 1 字）。
**自建构建脚本**：默认 env 只设 `VERT_TMP`，构建完单独跑
`src/tools/fix_tounicode_circled.py <pdf> <lines> --fix-json <fix清单>`。

### 2.3 单页验证不能只看 `build_vert.py` 的产物

它会漏 `fix_tounicode_circled` 后处理 → 圈码 `⑩` 在 `.tex` 里有、PDF 文本层里没有。
**验证圈码/丁巴特字符要看 `.tex` 源或跑过后处理的 PDF。**

### 2.4 等价性判据

```
✅ 比 .tex 源码 md5（确定性）
✅ 比 PDF 逐页文本 / 字符量
❌ 比 PDF md5（含 CreationDate，必然不同）
```

### 2.5 数据口径

```

lines/coords = 0-based 索引（产品页 p 对应 str(p-1)）
```

## 四、方法论（本轮最值钱的部分）

### 4.1 判据设计的铁律

```
① 先拿【用户确认的正例】标定判据，再推全书。拿想象的正例标定必然错。
② 一个判据在 >75% 的候选上都报警 → 它是噪声，不是判据
   （实测：R2 判据 1313/1748 页 → 标定后 0；圈码 hole 放宽后 350/366=96% → 判据失效）
③ 缺某个符号的规模必须数【产物 PDF】，不能数 OCR 数据（lines.json）
④ 参考系必须是【版面格】（列距/字步进/列框），不是字形 bbox
⑤ 定位锚点必须是 char['origin']（布局算的），不是 char['bbox']
⑥ 双向标定：≥3 个已知「该有」必须报出，≥3 个已知「不该有」必须为 0
⑦ 竖排汉字字形在 y 方向是【互相贴着】的 —— 「沿列 y 切墨段、段数>字数」原理上不可用
   （实测 p1683 一列 5 字，合并 3pt 后只切出 2 段）
```

### 4.2 「参考系错」是本项目最高频的失效模式（累计 7 次，全部无声无息地给出看起来正常的数字）

```
灰度数组直接 .mean() 当密度      → 打印出 fill=191.56、密度 188%
两格合成一个 box 量密度          → 「一格有墨」被算成「整条存在」
char['bbox'] 当版面格            → 竖排 bbox 高≈3× 字号，天然圈进邻字
                                   （实测两类候选 bbox 尺寸一模一样 79.3×31，分类毫无区分度）
按 docstring 文本插代码          → 插进没有该参数的兄弟函数，运行时才 NameError
按文字层上下文推断物理内容        → 把 p1742 的異體字表当 OCR 乱码
按 OCR 数据当产物                → 「冒号后缺引号 134 处」白改一轮
按单列自己的框高/字数当步进        → 短列 13.4 vs 真实 18.5，窗口把圆环裁掉
```

**动手前必问：这个判据的分母 / 参考框 / 定位锚点是什么？它是版面量还是字形量？**

### 4.3 汇总：本轮我在判据上错了 10 次

```
破折号      5 次  灰度当密度 / 两格合一 box / bbox 当参考框 / 判据太粗 / 異體字表当乱码
圈码        3 次  ctr 设上界 / 步进口径 / hole 当必要条件（未解决）
冒号引号    1 次  拿 OCR 数据当产物
wz6 边注    1 次  把「正确行为」当成「回归未收」
```

用户每次都是拿**具体页码 + 截图**把我拉回来的。这是本项目能往前走的唯一有效机制：
**用户指页码 → 助手用源图墨迹核验 → 改判据 → 全书复扫 → 双向标定 → 交付**。

## 五、未解决问题（按优先级）

### P0-a　两位数圈码（49/50/51…）检不出 —— 判据需换

**现象**：用户实测 p1704 的 49、50「一样大的圈还在」，产物是普通数字；往后 p1705/1706 的 51/52 同样。

```
p1704  圈码 []      数字 ['４９'×4, '５０'×3]
p1705  圈码 []      数字 ['５０','５１']
p1706  圈码 []      数字 ['５１'×5, '５２'×10]
```

**根因**：两位数把圈心填满 → `binary_fill_holes` 找不到洞 → `hole ≥ 0.10` 拒掉。

实测（900dpi，列末一格）：

```
p1684 ⑫   主块 18.0×18.0pt   hole 0.17-0.22   ← 单个宽数字，圈心还留洞
p1704 49  主块 16.5×15.8pt   hole ≈ 0.05      ← 两位数字填满，没洞
p1704 50  主块 16.5×15.2pt   hole ≈ 0.05
```

**试过并失败**：

```
hole ≥ 0.10 → 0.00     全书 184 → 350 处，而列尾是数字的列总共只有 366 → 命中率 96%，判据失效
窗口「列底 1 格」→「列末 2 格」   184 → 156，反而更差 → 窗口不该动，要改判据
```

**建议方向**（未实施）：去掉 `hole` 必要条件，改**收紧主块尺寸**到 `15.5–19.5pt`
（实测圈码 16.5/16.5/18.0/18.0；普通数字字形只有 8-13pt）。

**⚠️ 动手前必须先补反例样本**：目前只有「有圈」的实测，
**没有「同样数字但印成普通」的反例**。用户书里应能找到（正文数字/页码），
量完再改 —— 否则会重犯「96% 都报警」。

简报：`docs/vert_taskH_ring2digit.md`（含正例/反例坐标、双向验收标准、复现命令）
