# 第一部分　系统全景

## 1. 系统是什么

**输入**：扫描书 PDF（或扫描图）→ **中间**：PaddleOCR-VL-1.6 行级 spotting OCR → **输出**：
① 版式还原的可搜索 PDF　② 供知识库/RAG 用的 Markdown

**核心设计目标**（用户原话）：
> 「我们要做的是一个系统，不是只针对这本书」

所以所有参数必须**数据驱动 / 自动标定**，禁止硬编码某本书的实测值。
换书验证必须用第二本书实测，不能靠推理。

## 2. 两层架构

## 4. 竖排的坑（横排不存在）

```
· 竖排汉字字形在 y 方向【互相贴着】→ 「沿列 y 切墨段、段数>字数」原理上不可用
  （实测 p1683 一列 5 字，合并 3pt 后只切出 2 段）
· 字步进不能用「框高 ÷ 字数」（短列 `。12` 三字算出 13.4 vs 整页真实 18.5）
  → 一律取「本页 n≥8 长列的框高中位」
· 引号开闭必须用方向量 bias=(c1+c2)-(c3+c4)；四角极差是 rotation-invariant，分不出开闭
· 竖排破折号 = 一个墨块，不是一个字格（p57 实测 1.26 格 = 80.2pt）
· \scalebox 与 \char"FE31 在 tate 文档里都是 Undefined control sequence（已证伪，别重走）
```

```
① 先拿【用户确认的正例】标定判据，再推全书。拿想象的正例标定必然错。
② 一个判据在 >75% 的候选上都报警 → 它是噪声，不是判据
   （实测：R2 判据 1313/1748 页 → 标定后 0；圈码 hole 放宽后 350/366=96% → 判据失效）
③ 「缺某个符号」的规模必须数【产物 PDF】，不能数 OCR 数据（lines.json）
   渲染端有多处墨迹驱动的符号修复（QSF 的 一→﹁/﹂、R2 破折号、段首圈点），
   OCR 数据里「少」的东西，产物里可能已经有了
④ 参考系必须是【版面格】（列距/字步进/列框），不是字形 bbox
⑤ 定位锚点必须是 char['origin']（布局算的），不是 char['bbox']
⑥ 双向标定：≥3 个已知「该有」必须报出，≥3 个已知「不该有」必须为 0
⑦ 竖排汉字字形在 y 方向【互相贴着】→「沿列 y 切墨段、段数>字数」原理上不可用
```

## 6.2 「参考系错」是最高频失效模式（累计 7 次，全部给出看起来正常的数字）

```
灰度数组直接 .mean() 当密度        → fill=191.56、密度 188%
两格合成一个 box 量密度            → 「一格有墨」被算成「整条存在」
char['bbox'] 当版面格              → 竖排 bbox 高≈3× 字号，天然圈进邻字
                                     （两类候选 bbox 尺寸一模一样 79.3×31，分类毫无区分度）
按 docstring 文本插代码            → 插进没有该参数的兄弟函数，运行时才 NameError
按文字层上下文推断物理内容          → 把 p1742 的異體字表当 OCR 乱码
按 OCR 数据当产物                  → 「冒号后缺引号 134 处」白改一轮
按单列自己的框高/字数当步进          → 短列 13.4 vs 真实 18.5，窗口把圆环裁掉
```

**动手前必问：这个判据的分母 / 参考框 / 定位锚点是什么？它是版面量还是字形量？**
