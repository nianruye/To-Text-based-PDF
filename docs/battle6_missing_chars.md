## E. 规模验证与修正

- 候选集（3,828 列）外推：汉字插入 **41/2000 = 2.05%** → **~78 处**（Wilson 95% CI 1.5-2.8% → 57-107）。
- 随机列样本（t24 的 241 列，1.2% 汉字）外推：23k 列 → **~276 处**（CI 90-830）。
- 综合：**可信真缺汉字 ≈ 100–300 处**（中心 ~150）；t24 的「300–400」**偏高**，修正为 **~100-300**；标点/引号/破折号另计（约 49/2000×3828 ≈ 94 处候选集，或 ~560 全列，重叠 taskE/F）。
- 原因：t24 的 241 列样本太小（3 个汉字），且未剔除端部上下文/破折号；2000 列试点把「真插入」拆成汉字/标点后，汉字率 2.05%，纠正了 1.2% 的小样本高估/波动。

## F. 结论与下一步

1. API 质量：25/25 批成功、无静默丢批；列条带准确（1,665 same + 90 插入），**上下文必需**（孤立单字不可用）；`——`/引号等符号需按 taskE/F 单独处置。
