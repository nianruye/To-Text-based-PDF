# 遗留：两位数圈码（49/50/51…）检不出 —— 圈心被数字填满，没有洞

状态：**未解决，需要换判据**（2026-10-24）
现行工具：`src/tools/census_ring_digit.py`（commit `31da624`，全书 184 处 / 42 页）
交付产物：v29（`wz7_金瓶梅词话_全书_v29_年表圈码终版.pdf`）

## 现象

用户实测 **p1704 的 49、50「一样大的」圈还在，但产物里是普通数字**。往后 p1705/1706 的 51、52 同样。

```
p1704  圈码 []      数字 ['４９','４９','４９','４９','５０','５０','５０']
p1705  圈码 []      数字 ['５０','５１']
p1706  圈码 []      数字 ['５１','５１',…]
```

普查列表里 **p1704 整页不在**，p1705 只有 1 处，p1706 有 6 处。

## 根因：两位数把圈心填满 → 没有洞

`hole`（`binary_fill_holes` 差集 / 面积）是现行判据之一（要求 `>= 0.10`）。

- **单个宽数字**（p1684 的 ⑫「12」）：圈心还留着洞，实测 `hole 0.10-0.30` → 能检出
- **两位数字挤在圈里**（p1704 的 49/50）：圈心被填满，`binary_fill_holes` 找不到洞 → `hole ≈ 0` → 被拒

p1704 行10 列底（x309.9, y940-985, 900dpi）的 ASCII：

```
.......+.......
......###......      <- 一条竖笔画
......###......
.......+.......
....+####......
....######.....      <- 一个实心团块（无环洞）
...+######.....
...+######+....
...+######.....
....#####+.....
.....+++.......
```

墨量 14.2%，**一个笔画 + 一个实心方块，没有环形轮廓**。

## 试过但失败的放宽

把 `hole >= 0.10` 改成 `hole >= 0.00`（其余不变），全书：

```
圆环检出  184 处 / 42 页  ->  350 处 / 57 页
而「列尾是数字的列」总共只有 366 处 / 60 页
=> 命中率 96%，判据已失去区分度（噪声，不是判据）
```

多出的页：p5 / p424 / p484 / p495 / p561 / p1127 / p1171 各 1 处（年表段之外，疑似假阳）。

同时把窗口从「列底 1 格」放宽到「列末 2 格」会让数**掉到 156 / 32**（更差），
说明加宽窗口引入了别的判据冲突 —— **窗口不要动，改判据本身**。

## 建议的判据方向：按「连通域个数」而不是「洞」

竖排里两种情形的物理差别是**墨块个数**：

```
普通数字（无圈）  两个独立小字形，各占一格，尺寸约 8-10pt
圈码（有圈）      一个紧凑墨块，约 16-19pt 见方（圈 + 圈里的数字连成一片）
```

所以判据改成：

```
在列末 1 格（不要加宽）内做连通域，取中位尺寸 ≥ 8pt 的分量：
  分量数 >= 2 且 各分量 <= 12pt   -> 普通数字，不动
  分量数 == 1 且 14 <= 边长 <= 23pt -> 圈码候选
再叠加原有的：ctr >= 0.15、fill <= 0.78、宽高比 0.6-1.7
hole 不再作为必要条件（p1684 的 ⑫ 仍会被上面几条接受）
```
