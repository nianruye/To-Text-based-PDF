> 2026-11-15 · 由 wz9 验收暴露的问题触发
> 结论：**是系统不足，根本原因是「没有版面语义模型，只有特征阈值集合」**

### 3.3 每书配置（当前唯一一本）

```json
// config/books/wz9.json
{"footnote_wrap": true, "image_pages": [5], "structured_toc_pages": [18]}
```

| 配置项 | 本该能自动判断的依据 |
|---|---|
| `image_pages: [5]` | 手写/影印页的墨迹特征与印刷页明显不同（连通域密度、笔画粗细分布） |

| `footnote_wrap` | 脚注自然宽 > 版心即应折行（但 ghbq 对 parbox 敏感，被迫隔离） |

**每一项都是一个「本该自动、现在人工」的能力缺失。**

## 4. 为什么不同 PDF 结果不一样

### 层 1：输入确实不同（合理差异）

| 差异 | 应该不同处理 | 我们做到了 |
|---|---|---|
| 手写稿 vs 印刷体 | ✅ | 部分（靠登记 `image_pages`） |
| 横排 vs 竖排 | ✅ | ✅（零代码耦合的两条管线） |
| 中文目录 vs 英文目录 | ✅ | ✅（新加 `structured_toc_pages`） |
| 图版 vs 照片 | ✅ | ✅（`_image_page_full`） |

### 层 2：OCR 输出形态不同（不完全可控）

| 书 | 目录页 OCR |
|---|---|
| wz1 | 每条一行，规整 |
| wz9 中文目录 | 每页 19–48 行，段落碎 |
| wz9 英文目录 | 25 行，含 `/1` 页码 |
| wz9 手稿页 | 乱码（177 字全错） |

**同类页面，OCR 给的结构完全不同** → 同一套规则必然覆盖不齐。

### 层 3：我们的判定（这是不足）

**同一排版意图，不同书用不同特征表达：**

| 现象 | A 书 | B 书 |
|---|---|---|
| 「加粗但字号不变」的标题 | ghbq：版面标签 `paragraph_title` 命中 | wz8_1：标签 `text`，几何无解 |
| 章标题 | ghbq：36pt，2.2× 正文，几何能救 | wz8_1：1.36×，几何判不出 |
| 目录 | ghbq：点线+页码，正则能认 | wz9 英文：`/1`，压成一段 |
| 脚注 | wz9：长脚注需折行 | ghbq：对 parbox 敏感，折行会崩 |

**根本原因**：

> 我们没有「版面语义模型」，只有「特征阈值集合」。
> 每本新书都在测试这个集合的边界，每撞一次加一个补丁。

## 5. 问题分类：共性 vs 个例

按 AGENTS「判据边界原则」重新分类当前所有补丁：

| 类别 | 判据 | 当前处理 | 应改为 |
|---|---|---|---|
| **共性** | 跨页、跨书复现 | 全局规则 | 保持（但要有置信度） |
| **个例页** | 只 1–2 页 | `config/books` 登记 | 期望自动判定 + 低置信降级 |
| **每书参数** | 影响全书 | 标定 + 人工调 | 标定 + 置信度 + 失败降级 |

**关键洞察**：现在的「个例页登记」不等于「放弃自动化」，而是**自动化还没做**。

## 6. 目标架构

### 6.1 现状

```
OCR 数据 → [38 开关 + 25 阈值 + 11 函数] → 直接拼 LaTeX → PDF
                    ↑
            判定与渲染混在一起（2076 行）
```

### 6.2 目标

```
OCR 数据 + 版面模型
      ↓
【版面判定层】每个元素给出 (类型, 属性, 置信度)
      ↓
【结构化文档模型】
   Page[]
     Block[]  (heading/body/toc/figure/caption/footnote/ornament)
       level, text, bbox, bold, size, confidence
      ↓
【渲染层】只消费模型，不含判定
      ↓
LaTeX → PDF
```

### 6.3 关键设计原则

1. **判定与渲染分离** —— 渲染层不能有 `if 字号 > 1.2倍 then ...`
2. **每个判定带置信度** —— 低置信时**降级为整页贴图**（保真优先于重建）
3. **降级可见** —— 产物报告里写明「p18 判定置信度 0.4，已降级为贴图」
4. **规则通用、数据逐页** —— 不是 `image_pages:[5]`，而是「p5 手写页置信度 0.3 < 阈值 0.6」

## 7. 三步迁移路线（不推翻重来）

### 第 1 步：抽出判定层（低风险，1–2 周）

**做什么**
- 新建 `src/pipelines/layout_model.py`：输入（lines + coords + layout json + 源页），输出 `DocModel`
- `build_geom.py` 改为消费 `DocModel`，判定代码整体搬走
- **行为不变**（重构），用逐页 diff 证明

**验收**
- 7 本书逐页文本 diff = 0
- `build_geom.py` 行数下降 ≥30%
- 判定函数全部搬入新模块

**风险**：低（纯搬运）。

### 第 2 步：给判定加置信度 + 降级（中风险，2–3 周）

**做什么**
- 每个判定返回 `(结果, 置信度)`
- 引入降级通道：置信度低 → 该块/该页走「整页贴图 + 隐形文本层」
- 报告里列出所有降级页与原因

**为什么这是最大收益**
- **新书不会再出现「4pt 文字」这种灾难** —— 标定置信度低就整页贴图，至少保真
- 用户拿到的是「有些页是图，但每个字都对」而不是「全文重建但错字连篇」

**验收**
- 构造 3 组低置信场景（手写页、乱标定、未知目录形态），产物均降级且报告可见
- 7 本书置信度均在阈值以上 → 行为不变

**风险**：中（新增通道，需逐本验证）。

### 第 3 步：把「每书配置」转成通用判定（长期）

**做什么**
- 手写页检测：墨迹连通域密度 + 笔画粗细方差 + OCR 置信度
- 英文目录检测：拉丁字符占比 + `Chapter` 形态（已有雏形）
- 脚注折行：只在「自然宽 > 版心」时启用（需先解决 ghbq 的敏感问题）

**验收**
- 删掉 `config/books/wz9.json` 里的 `image_pages` 与 `structured_toc_pages` 后，wz9 结果不变

**风险**：中高（触及判定核心）。

## 8. 不做的代价

| 现状 | 继续下去的后果 |
|---|---|
| 每本新书 ~12 个补丁 | 补丁越多，互相干扰概率越高（本次实测：改脚注折行让 ghbq 104→79 页）|
| 补丁靠人名/书名隔离 | `CALIB_BOOK=='wz9'` 这类特判会继续出现 |
| 没有置信度 | 标定崩了也硬渲染（wz8 曾出 4pt 全文） |
| 用户看到的是「结果不一致」 | 无法建立「上传任意 PDF 就有可信结果」的预期 |

**最大的风险不是慢，是「每修一处都可能坏另一处」** —— 本次会话实测 3 次：
1. 脚注 parbox 通用化 → ghbq 104→79 页
2. 目录序号规范化 → wz1 `十一` 被拆成 `十 一`
3. `\null` + `_outside_text` 同时改 → fit_positional exit 1

## 10. 建议决策

| 选项 | 工作量 | 收益 |
|---|---|---|
| **A. 只修 wz9 剩余 4 项** | 2–3 轮 | wz9 达到可交付，其他书不变 |
| **B. 做第 1 步（抽判定层）** | 1–2 周 | 为后续能力打地基，行为不变 |
| **C. 做第 1+2 步（判定层 + 置信度降级）** | 3–5 周 | **新书不会再出灾难性结果** |
| **D. 做完整三步** | 2–3 月 | 真正的「上传即用」 |

**我的建议：C。**

理由：
- 第 1 步是纯重构，风险低，但单独做没有用户可见收益
- 第 2 步（置信度 + 降级）是**用户可见质变** —— 从此不会出现「4pt 全文」或「手稿乱码」
- 第 3 步（通用化判定）可以按遇到的书逐步做，不必一次到位

**具体第一步动作**：先做第 1 步重构，用 7 本书逐页 diff = 0 证明无回归；再做第 2 步的降级通道，用「构造低置信场景」验证。
