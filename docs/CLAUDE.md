# PDF 排版还原系统 (To-Text-based-PDF)

## 项目概述

将扫描型 PDF（图片格式）转换为文字型 PDF，完整还原源文档的排版结构，包括正文、标题、脚注、页眉、页码等区域的位置和样式。

**GitHub**: https://github.com/nianruye/To-Text-based-PDF
**工作目录**: `/opt/test`

## 核心架构

### 处理流程
```
PDF → PaddleOCR-VL-1.6 spotting → 结构化数据
  → 区域检测（正文/脚注/页眉/标题/页码）
  → 区域面积计算 → 动态行间距/字间距 → xelatex → PDF
```

### 关键文件
- `build_geom.py` — 几何区域驱动方案（当前主力）
- `build_pdf_v13.py` — 逐字排版方案（基准参考）
- `build_pdf_v12.py` — 早期版本（已存档）
- `verify.py` / `check_quality.py` — 质量检测脚本

### OCR 依赖
- PaddleOCR-VL-1.6 API（百度 AI Studio）
- API Token：通过环境变量管理，不能写死在代码中
- spotting 模式：逐行获取文本位置和内容
- 不支持内嵌图片的 PDF

## 已知问题与待解决

1. **行间距控制**：不同书、不同区域的间距还原不准确
2. **字体识别**：宋体/楷体/黑体区分，加粗/斜体检测仍不完美
3. **标题层级**：无序号标题的识别，目录辅助标题定位
4. **空白/溢出**：区域填充算法仍会产生空白或内容溢出
5. **标点间距**：中文标点后的半角空格处理因书而异
6. **古籍排版**：夹注、旁注、多栏排版的识别和还原
7. **页码还原**：页码位置和内容需要与源文档一致

---

## 设计原则

1. **通用性**：系统处理逻辑不能针对特定 PDF 硬编码参数
2. **区域驱动**：先检测页面各区域（正文/脚注/页眉/标题），再在各区域内排版
3. **动态适配**：参数通过分析源文档动态计算（中位数等），非固定值
4. **版本控制**：重大改动前存档，通过 git 管理
5. **隐私安全**：API Token 等敏感信息不写入代码，通过环境变量管理
