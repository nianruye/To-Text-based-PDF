## 0. 一句话目标

**在渲染端（`col_puts` 里已经有精确格位坐标的地方），对「末格 OCR 字是 `。` 或 `一`」的单元格回源图量墨迹形状；若是直角形（引号），把该码位改成 `﹂`。**

不做引号余额配对、不改版面、不动任何坐标。

## 1. 现象：用户实测 p444

源书这一列：`宋仁爲女歸陰路，致死冤魂塞滿衙。﹂`
- OCR 文本：`致死冤魂塞滿衙。`（末字给成 **`。`**）
- 我们照 OCR 画出来，用户看到的是句号，**缺闭引号**

同页另一列：`溟冷飢鬼揮鍾馗。﹂`
- OCR 文本：`溟冷飢鬼揮鍾馗。一`（末字给成 **`一`**）
- 同样画错

用户原话：「源书有的呀 而且我发现好多这种诗句都没有闭引号，是ocr本来就没有识别出来吗」

**答案：是 OCR 认错了，不是源书没有。**

### 1.1 像素证据（600dpi 直接量，别再用视觉模型）

p444「致死冤魂塞滿衙」列末（`x512-548, y800-850`，阈值 185 的 ASCII 墨迹图）：

```
y814.6-820.6   x529-534   一条竖画
y821.4-823.5   x529 向右延伸的横画
y828 以下      空白
```

→ **竖臂 + 横臂构成的直角 = 引号**，不是圆圈。

对照真句号（同页「大暑無過丑申，大寒無過丑寅」列内倒数第二格）：
```
墨迹 7.2 x 7.4pt   四角密度 0.43/0.56/0.33/0.57（均衡）  中心 0.06（空）
```
→ 闭合圆环 = 真句号。

### 1.2 国标依据

GB/T 15834-2011《标点符号用法》：
- **4.8.3.5**：「独立成段的引文如果只有一段，段首和段尾都用引号；不止一段时，每段开头仅用前引号，只在最后一段末尾用后引号。」→ **引文末尾必须有后引号**
- **5.2.3**：「引号改用双引号"﹃""﹄"和单引号"﹁""﹂"，括号改用"︵""︶"，标在相应项目的上下。」→ 竖排用 ﹁﹂
- **5.2.6**：「横排文稿中关于某些标点不能居行首或行末的要求，同样适用于竖排文稿。」→ 后引号不能居列首（现有 `[禁则归位] 行首闭括号回上一列` 行为是正确的，**不要动**）

所以补 ﹂ 既还原源书排印、又符合国标。**不是"美化"，是纠错。**

## 2. 根因：为什么必须做在渲染端，不能做外部工具

主控（Hermes）已在外部写了三轮形状分类器，**全部失败**，失败点都是同一个：**拿不到只含一个字形的那块图**。

| 版本 | 做法 | 结果 | 失败原因 |
|---|---|---|---|
| v1 | 「有角>0.30 且 中心空」判直角 | 2/4 | 判据太松，圆环四角也>0.3 |
| v2 | 「四角极差 ≥0.35」判直角 | 6/9 | 裁窗口含相邻字，四角特征被污染 |
| v3 | 先按墨迹连通段切字再分类 | 0/7 | 分段脚本本身写坏（阈值 200 在整列上找段，要么找到 1.4pt 噪点、要么整列连成一段） |

**关键教训（写在最前面，不要在外部工具里重复这些错）**：

1. **判「源书有没有」不能用单一阈值一次定**：阈值 185 会把浅墨当噪点滤掉（p444 的 ﹂ 只有 1.3pt 高），必须多阈值对照或直接打 ASCII 像素图。
2. **裁图窗口必须只装一个字形**：窗口含相邻字时四角密度特征会被污染。实测真句号只有 7×7pt，被下方那个字拉成 21×29pt → 误判 corner。
3. **视觉模型不可靠**：DeepSeek 视觉实测 3/4，会漏看细竖臂（把直角看成横线），且同一张图两次可能给不同答案。**不要在主链路里调视觉模型。**
4. **外部工具猜位置 vs 渲染端知道位置**：`col_puts` 画每个字时**本来就要算出这个字画在哪一格**（不算就画不出版面）。在那个位置回源图取样，窗口天然精确。这是本任务成立的全部理由。

## 3. 要改的地方

### 3.1 主改点：`src/pipelines/build_vert.py` 的 `col_puts`

`col_puts(t, xc, m2, sl, pi)` 负责把一行文本按槽位铺开。函数体内有对每个字的循环（形如 `for i, ch in enumerate(t)`），循环里已经算出：

- `step`：字步进（pt）
- 第 i 个字在列内的 y 位置（`T` 起算，逐字累加 step）

**在这个循环里，对最后一个字（`i == len(t) - 1`）加一步检查**：

```
若 ch ∈ {'。', '一'} 且该行不是目录页行/不是特殊行：
    取该字所在格位的源图墨迹（x = 该列 x 带，y = [该字 y0, y0 + step]）
    判形状：
        corner  → 把 ch 改成 '﹂' 再渲染
        ring/bar/other → 不动
```

**注意**：取源图用现成的 `src_gray(pi)`（`note_cols` 里已在用），不要新开 fitz 句柄。

### 3.2 取样窗口的精确口径（这是成败关键）

```
x 范围 = 该列（槽）的 x0 .. x1，向两侧各让 2pt 收紧（避开邻列渗墨）
y 范围 = [该字的格顶, 该字的格顶 + step]
```

- **不要**用 OCR 的 poly y 范围去猜（OCR 的字数可能本身就是错的）
- **不要**用「列底 1.4 格」这类宽松窗口（v2 就是这么错的）
- 格位必须来自 `col_puts` 自己算的 T + i×step，这才是权威

若该格墨迹像素 < 阈值（比如 < 40 个暗像素）→ 判「该格无墨」→ 不动，并记日志（可能是 OCR 多给了字，不在本任务范围）。

### 3.3 形状判据（已由 8 个人工标注样本反推，**不要改判据，只许改取样位置**）

在墨迹包围盒内归一化后计算：

```
c1 = 左上角区(30%x30%) 墨密度      c2 = 右上角区
c3 = 左下角区                      c4 = 右下角区
ctr = 中心区(中间 40%x40%) 墨密度
top/bot/lef/rig = 四条边带(各 20% 厚)的墨密度
四角极差 spread = max(c1..c4) - min(c1..c4)
```

分类：

```
bar    : 宽高比 >= 1.8 且 高 <= 0.30 × 字格边长
         （真「一」：单条长横，无竖臂）
corner : spread >= 0.35 且 max(c1..c4) >= 0.40 且 ctr <= 0.45
         （真引号：一个实心交点角 + 两条臂）
ring   : ctr <= 0.35 且 min(top,bot,lef,rig) >= 0.05 且 spread < 0.35
         （真句号：闭合圆环，四角均衡）
other  : 其余（不动）
```

参考实现见 `tmp_vert/cj5/shape_clf2.py`（`analyze()` + `classify()`），**可以直接复用这两个函数**，它已经能正确算出特征（v2 的 6/9 全是窗口错，不是特征错）。
