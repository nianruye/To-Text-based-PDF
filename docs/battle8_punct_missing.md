## 3. 每类落库可行性与风险

### 3.1 `」`/`「`（40 条）——建议 QSF 扩展后插入
- **可行性**：源图角形明确（8/8 抽样），插入 1 个引号不改变列宽（竖排整格），文本层 +1 字。
- **风险**：
  ① 直接走 `missing_char` 会与 QSF 的「闭合不补」口径冲突：QSF 只在**行首闭引号**与开引号栈配对时补/移；单纯插入 `」` 可能造成「无开引号的闭引号」或与 `fix_split_brackets` 的移字顺序再次错位（t32 已用上下文重定位缓解，但引号配对仍需栈校验）。
  ② 插入位置在列尾/列首时，`_relocate_missing` 的上下文匹配可能落在邻列（需限定在本列 x 带内）。
- **建议实现**：在 QSF 路径内加「引号补全」分支：行首/行尾角形墨 → 查本页开引号栈 → 配对才补；补后不参与 dash/ring 逻辑。

### 3.2 `——`（46 条）——不建议按破折号插入
- **风险**：抽样 8/8 不是破折号；若把 `——` 塞进文本层，t34 rule 会按「相邻两个 `—`」去画 rule，**在引号位置画出长竖线**，比缺字更糟。
- **建议**：按 §3.1 的 QSF 引号路径**重判**（这些很可能是 ﹁/﹂ 被 API 读成 `——`）；重判为引号的，走 3.1；仍不确定的留白。

### 3.3 `—`（1 条，p57）——先查 dash rule
- 源图粗竖线（疑破折号）。若 t34 的 `_dash_ink_seg` 在该列能量到墨段，则插入 1 个 `—` 后 rule 会画出；量不到就不插（宁缺毋滥）。

### 3.4 `，`（2 条）——逐条复核
- p147 疑真、p1330 噪点。建议按行内上下文（前后 3 字）确认后再走 missing_char。

### 3.5 `〇`（1 条，p148）——走 ring/census
- 圆圈墨块，应作为 **ring** 条目（1:1 占格元素），不走 missing_char；census 37 条未含 p148，下一轮补一条 ring。

### 3.6 不建议插入（6 条）
- `H`（p78）、`8`（p1729）、`】`（p450）、`）`（p985）、`」「`（p693）、`」。`（p186）——源图分别是「讀/〇/聲/沙/醒/…」，API 误判；插入会造错字/错标点。

## 4. 建议实现顺序（下一轮）

1. **QSF 引号补全分支**：处理 `」`/`「`（40 条）+ `——` 重判后的引号（预计 30-40 条）——收益最大、风险可控（配对 + 角形墨迹双闸门）。
2. **t34 dash rule 复核 p57 `—`**（1 条）：能画 rule 再插。
