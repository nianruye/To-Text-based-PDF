## 2. 实现（`src/pipelines/build_vert.py` §1.98）

1. **逐页版框**：复用 `frame_geom`（§1.95）；**槽格 = 墨迹列带栅格**（`_ink_bands` + `_grid_from_bands`）——
   界行线淡的页（p22/p32/p36）版框兜底栅格把内框宽算成 511pt（真值 522），12 等分后左端偏 6pt、槽切到列缝上
   （p32 槽内 run 数 25→11、字号被算成 873pt）；改用「字」的墨迹列带定栅格后自愈（120 页做了 ≤7.2pt 的相位校正）。
2. **逐槽实测**：槽内墨迹 y 投影 → 字 run（x 内缩 3.5pt 避界行线、y 内缩 2pt 去版框横线、剔 >3× 中位的异常长 run）
   → 每槽 `nr/hm/step/top/bot`；槽分类：`hm >= 0.75×最大` = 正文槽，更小 = 双行小字注槽。
3. **墨带/字号/步进**（逐页，数据驱动）：墨带 = 正文槽首/末 run 上/下缘中位；字号 = 正文槽 run 高中位 ÷ 0.88
   （`INK_RATIO`，probe 标定）；步进上限 = run 间距中位。合理性校验：字号须 ∈[10,60]pt 且墨带高 ≥ 0.4×内框高。
4. **正文行 ↔ 槽**：OCR 行按字步进二分（正文/注，阈值 1.18 —— 单字号页实测 ≤1.13），短行（<8 字）按源图槽区归属；
   同列断行先合并（`_merge_col_rows`）；行数=槽数时按序 1:1 直配（195 页），不等时单调 DP（只允许多的一方跳过，
   代价 = |OCR 字数 - 槽 run 数 - 页内中位差|）；双行小字页（24 列/12 槽，实测 5 页）按 2 倍子列重建槽位。
5. **渲染**：逐字 `\put`（eso-pic 带星版）绝对定位 —— 实测 tate 下 FG 图内文本沿页 x 横排，必须逐字定位；
   坐标标定：`put y = (page_h - Y) × 1.00375`（pt→bp），列墨迹顶/底命中目标 0.00pt。逐字 put 不占版心流，
   顺带消除「列数超容量多出页」的隐患。列高规则见 §4。
6. **边注/书眉/页码**：仍用源图墨迹实测（旧 `note_cols` 聚类，新增可选区带参数），但区带改由**注槽 x 带 + 注行 y 带**
   给出（旧判据 x0<100 在 p162 把版心内注行漏掉、且首列短行被误当注 → 错位重影）。

## 4. 与任务书第③条的字面差异（如实报告）

任务书要求「所有正文列顶贴内框顶、底贴内框底，字距按字数自适应」。实测**源书并非如此**：
- 满列（源槽墨底到墨带底 ≤3 字步进）：底贴墨带底、字距 = (墨带高-单字墨高)/(字数-1)，实测源书满列底缘 1093.0-1099.5；
- **短列（段尾/标题）源书是「顶贴墨带顶 + 源书常规字距」，不拉伸**：p100 首列「的了。」源 330.0-390.5（3 字）、
  「究這三個問題。」330.0-514.0（7 字）；标题列接排（源 422.5 = 上列墨底 390.5 + 32.0）。
  若按字面把 3 字列撑满 770pt，字距 370pt，即为乱排。
→ 实现取「源书惯例」：满列底齐（这就是「列底对齐」的实现方式），短列顶贴/接排（不拉伸）。
**因此「每页所有正文列列底极差 ≤10pt」只在满列上成立**（短列底必然不齐，源书亦然）；
p100 满列 7.5pt、p99 满列 1.5pt（早前版本曾出现 69.1pt，是把源书满列误判为短列所致，已修）。
短列全书占比 8.5%（212/2485 槽），135/228 页各有 1-3 条。

## 8. 代码改动（`src/pipelines/build_vert.py`）

1. **`col_puts` 列顶/列底改为「本槽实测」**（§1.98，签名 `col_puts(t, xc, m, sl, prev_bot)`）：
   - 列顶 = 本槽实测墨迹顶。源书 87.5% 正文列顶贴墨带顶、9.9% 是段首缩进列（「空二字」，实测缩进中位 2.4 格、覆盖 158/222 页），少数标题列——数据自带，不再用启发式；
   - 满列（本槽实测底贴墨带底，2308/2551 = 90.5%）：步进 = (槽高 − 单字墨高)/(字数−1)，夹在常规步进的 0.75-1.30 倍 → 顶、底两端同时贴源书；
   - 短列（段尾/标题）：顶贴本槽实测顶 + 常规步进，不拉伸（源书亦然）；
   - 护栏：列不越过「本列终点」（满列 = 本槽实测底，短列 = 页正文块下缘）。
2. **`page_metrics` 槽顶/底测量三修**（原测量的三类系统性误差，实测驱动）：
   - 长 run 剔除只用于字号/步进估计；槽顶/底改走「全墨迹」口径，只剔**贴扫描窗口边**的版框横线 run（全书 2640 槽里原口径有 8 槽底、4 槽顶被截断，最大 471pt：p149 c1 底 611 vs 真值 1082.5）；
   - 细碎 run（高 <4pt：「三」「一」的分离点画、省略号点）按 0.7 步进贴回最近字 run（p50 c12 源列首「三」331.0 原被算成 360.0 → 列顶偏 29pt；p153 c9 列尾省略号同理）；
   - 槽顶/底用**深墨掩膜（<110）**：扫描透印（背面文字反透）在 150 阈值下会与本文粘连成一条竖贯 run（p90 c12 真列顶 ~380 被算成 853，整列被排到版框底部）；抽样 876 槽中两阈值 99.2% 一致（中位差 0.0pt），有差异的 7 槽深墨口径均更完整；
   - 墨带顶/底改「偏满列的一半」中位（原全槽中位会被缩进列/段尾列带偏：p18 半页短列 → 中位底 1068 而满列底 1099.5，差 31pt）。
3. **`page_rows` 页外行（书耳/篇名）判据收紧**：x 带与内框不相交**且**「版框最外一条线之外确有墨迹」才算页外，否则交回正文参与列对齐（p228 最左列「合當時反對北洋軍閥段祺瑞的西南軍閥組織反段的軍政府。」OCR x 5-26pt 落到内框外，旧判据当页外 → 该行 26 字丢失/或被错配到右侧列上）。
4. **`note_puts_frame` 页外区带夹到内框之外**：OCR 对边缘行的 x 会误置，旧实现按 OCR x 找墨迹会找到正文首列的墨 → 小字压在正文列上（p162「方面的問題」x525-546 压在第一列 × 5 字）。

## 10. 遗留（本轮新增实测）

1. **扫描透印带偏的 5 列**（p90/p94/p122/p28/p78 的 c12 = 订口侧首列）：透印与本文在深墨阈值下仍粘连，槽实测顶比真列顶低 130-500pt，该列被排到版框下半（顶部偏差 291.6pt 即来自此）。**顶偏差 p90 = 1.3pt、这 5 列占满列 0.2%**；下一步可做「行墨密度/连通域形状」区分透印。
2. **7.9% 列短 6-10pt**：OCR 行字数 < 源书格数（OCR 漏字/标点）→ 被步进上限夹住。放宽上限会让字距过松（视觉代价），暂留。
3. **5 页仍走 v2 流式回退**（p3 章题页 / p156 / p199 / p210 / p229 插图页）：这些页列底不齐、p3 有 4 处 span 越内框右缘 12.5pt（旧拟合右缘 594.9 的残留）。判据（墨带/字号合理性）本轮未改。
4. 标点仍按整格排（源书「。」挤在上字格右下角、不占格）：造成短列底整体偏下约 1 格（短列底偏差中位 21pt 即此项），未做竖排标点压缩。
