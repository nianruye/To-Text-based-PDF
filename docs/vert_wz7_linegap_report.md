## 1. 任务 A：短列被静默丢弃（`又曰：`）

### 1.1 对账（助手脚本 `/tmp/check_key54.py` 复核）

| 量 | 值 |
|---|---|
| OCR `key54` | 12 行 / **229 字**，标点齐全（含行5/行8 的 `又曰：`） |
| taskR2 基线 `R2a.pdf` p55 | **223 字**，`difflib` 相似度 98.7%，**唯一差异 = 两个 `又曰：`（delete 6 字）** |
| 本轮 `S300.pdf` p55 | **229 字**（差 0） |

### 1.2 根因：三条列带路径的**覆盖率分母是整页版心高**

源书该页 12 列 = 12 条 OCR 行；`又曰：` 是 3 字列，墨迹只占版心高的 **2.4%**（实测该列
x-projection 最大覆盖率 **0.024**，因为整列只有「又 + 曰 + 冒号两点」三条短 run）：

| 路径 | 判据 | 该列结果 |
|---|---|---|
| `_ink_bands`（列带检测） | 覆盖率 > `NF_COV=0.12` | ✗ 漏 |
| `nf_fill_bands`（残余补带） | 覆盖率 > `cov_lo=0.04` + 文字列证据 | ✗ 漏 |
| `_nf_rescue_rows._ocr_band`（行补救） | 覆盖率 > 0.04（整版心 y 窗） | ✗ 漏 |

→ 12 行对 10 槽 → `_align_rows_slots` 把两条短行当「多出来的行」丢掉（DP 罚 8 字）。
**连带后果（用户反馈①的另一半）**：丢掉的列带使槽边界（相邻带心中点）被推向邻列 ——
邻槽的墨迹跨度/run 序列被污染（实测槽 t=221.5 而该列首字墨顶 347），`fit_gaps` 为解释多出来的
跨度在**错位置**插空格（基线 6 列共插 20 格，位置分布错乱）。

### 1.3 修法（§1.976）：把**覆盖率的分母换成「该行自身的墨迹窗」**

版心内的**非长行**（= 短列，有真实 OCR 文本）自带 x 心与 y 带；在该窗内找墨迹列，
**三道判据缺一不可**（判据条数未放宽 —— 分母换了，阈值反而从 0.04 提到 0.05→密度 0.12）：

| # | 判据 | 取值 | 该页实测 |
|---|---|---|---|
| ① | 窗内 x 投影覆盖率（**候选**生成） | ≥ `NF_SB_COV=0.05` | 0.14（又/曰 各 19.5pt / 窗 137pt） |
| ② | 候选带**自身墨迹包围盒**内填充率 | ≥ `NF_SB_DEN=0.12` | 0.41（单个 5×5 噪点斑 = 0.01 → 挡下） |
| ③ | **字证据**：整版心量该带 run ≥ 2 且**字高** ∈ `[0.5,1.35] × 本页列带参照字高` | — | run 4 条 / 字高 19.5 vs 参照 23.0（0.85 ✓） |

「字高」用 run 高的 **75 分位**（`_big_hm`），既排标点碎片（小）也排并字长 run（大）：
该列 4 条 run = 又 19.5 / 曰 19.0 / 冒号两点 4.5+4.5，全 run 中位 11.75（会把字号算成 13.6pt），
75 分位 = 19.5 ✓；而「宿盡閒花…」列最大 run 48pt 是**萬萬并字**，用「最大 run 的比例」口径会把
字高算成 48pt，75 分位仍取 22.5 一档 ✓。

短列检出后进伪槽格；由 §1.976 补出来的槽，`_metrics_finish` 用**字 run 字高**判它是不是正文槽
（否则 4 条 run 里 2 条是标点 → 全 run 中位 11.75 < 正文槽门限 17.6 → 被判「小字注槽」→ 该行被
`page_rows` 划到注 → **整列再次丢失**）。两处短列都仍按 §1.976 的列带进 `body`，但**不进**
`band_t/band_b` 的取中位样本（短列按定义短于正文块；混进去会把「上半/下半」取中位的下标整体挪一格
→ 墨带底 1101 → 961，实测所有满列被判成短列不再拉齐列底）。

> 位置：短列的列带**不进** `_nf_fix_page` 的「列带 ↔ 行」仿射配对（那里的配对是长行对长列）——
> 否则 x 尺度会被拟成 1.416（真值 1.332）→ 映射后越界被拒 → 整页掉回未标定坐标系。

## 2. 任务 B：列内空隙误判

### 2.1 根因：**「标点挤格不占格」是 wz6 的排印习惯，不是普适常量**

现状的格口径（`n_cells`/`char_cells`/`fit_gaps`/`col_puts` 四处同源）来自 wz6 实测：
标点挤在前一字格右下角、**不占格**，下一字仍在「前字格顶 + 1 格」。

在 wz7 上逐 run 反推（源页 354 列 x763.5-786「沒來由暴叫如雷，你怪俺全無意。不思量自己，
不是你憑媒娶的妻！」30 字 4 标点，字步进 25.75pt）：

| 字序 | 0..6 | 7 | 8..13 | 14 | 15..19 | 20 | 21..28 | 29 |
|---|---|---|---|---|---|---|---|---|
| 实测格号 | 0.00-5.96 | ，7.26 | 7.94-12.93 | 。14.16 | 14.97-18.80 | ，20.14 | 20.87-27.57 | ！28.68 |
| 占格模型（= 字序） | ✓ 残差 ≤0.26 格 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 挤格模型（旧） | ✓ | ✓ | ✗ 每处标点后整段 -1 格（0.94-1.03 格） | ✗ | ✗ | ✗ | ✗ | ✗ |

即**该书的标点独占整格**（字形小、墨迹画在格内，实测墨顶 = 本格顶 + 0.26-0.37 步进）。
用挤格口径渲染的后果正好是用户的两条症状：
① 标点被画在 `(前格顶 + PUNCT_DY=1.128 步进)` = **下一字格内 0.128 格处** → 与下一字**重叠**；
② 整列少算 `n_punct` 格 → `fit_gaps` 为凑跨度把空格插到**标点之后**（「标点后字被隔开」），
且各列步进各自被拉长（「空格大小不一样」）。

### 2.2 修法：`PUNCT_CELL` —— 按本书源图墨迹标定「标点是否独占一格」

* 口径（§1.956 标定趟，`_calib_punct_cell`）：一列的墨迹跨度对应
  `N 格 = (墨迹底 − 字run墨顶 − 字高)/步进 + 1`；文本在两种排印习惯下需要 `N0 = 字数 − 标点数`（挤格）
  或 `N0 = 字数`（占格）→ `估计 = (N − N0_挤格)/标点数`（0 = 挤格 / 1 = 占格，含排版空格的列偏高，
  取**中位**稳健）。样本 = 每列「run ≥ 6 且 ≥ 1 个标点」的记录。
* 实测：**wz7 193 槽 → 中位 0.990 → PUNCT_CELL=1**（占格）；**wz6 178 槽 → 中位 −0.113 → PUNCT_CELL=0**
  （挤格，与既有行为逐字节相同）。判据阈值 0.5（格号是整数，只能二选一）。
* 影响面（四处同源，`§1.0a0` 注释）：`n_cells`（排版格数）/ `char_cells`（逐字格号）/
  `fit_gaps`（DP 预测锚点）/ `col_puts`（标点是否推进格号）。标点的**摆位公式不变**
  （锚点仍是前一字格顶 = 循环变量 k−1），只有**格号推进量**随 `PUNCT_CELL` 变。
* 占格口径下，标点**参与** run 匹配（它的墨在格内位置稳定，是 4 个对齐锚点）；挤格口径下仍不参与
  （wz6 实测：冒号墨心在格缝上，拿它匹配会把整列带偏）。
* `PUNCT_DY/GAP_HANG` 的**标定锚点语义**（相对前字格顶）与 `PUNCT_CELL` 无关，标定代码显式
  `− PUNCT_CELL` 抵消，故标定值不随口径变。

### 2.3 空隙判据（判据本身未改，改的是喂给它的**格模型**）

`fit_gaps` 仍是「DP + 格内无墨校验 + 落点不得停在标点前」；本轮只把它对齐的**格号**换成按本书
标定的口径。p55 空隙清单（本轮 `tmp_vert/taskS/gaps_S300.json`）：

| 列 | 文本 | 插入位置 | 格数 | 源书 |
|---|---|---|---|---|
| x641.5 | 宿盡閒花萬萬千，不如歸去伴妻眠， | `[[8,2]]`（，之后、不之前） | 2 | 2（实测格号 0-7 / 10-17） |
| x597.0 | 雖然枕上無情趣，睡到天明不要錢。 | `[[8,2]]` | 2 | 2 |
| x463.5 | 任君斗量并车载，難滿虔婆無底坑。 | `[[8,2]]` | 2 | 2 |
| x327.5 | 幾多伶俐遭他陷，死後應知拔舌根。 | `[[8,2]]` | 2 | 2 |
| x373.7 | 假意虛脾恰似真，花言巧語弄精神， | `[[5,1],[8,1]]` | 2（总格数 ✓，1 格落位偏差） | 2 |

**空格宽度**：同页所有列的步进 25.35-25.45pt（源书 25.0-25.8）—— 空格 = 该列 1 格 = 该列步进，
同页同书一致；列间差异来自源书自身列距差异（实测源书 25.0-25.8）。

### 2.4 「不得全局关闭 gap」的声明

`GAP_ON` 默认仍为 1，wz7 上检出 **5 处/10 格**（基线 6 处/20 格）；关掉 gap 会让源书确实存在的
诗句间空档消失（对照图：源书两行诗句之间有明显空档），故**没有**按书关闭。

## 5. 遗留（如实报告 + 选项）

1. **p286 −3 字**（413 → 410）：该页是 705×1084pt 小开本，源书页码「五六四」被 OCR 当成一行
   （x 647.9-669.8，在伪版心右缘 610.2 之外），本轮改好的行槽配对把这一格让给了真正的正文行
   `某月日。李通判韃子，限三日內返回原籍。`（19 字，基线靠「短列补救」渲染在**页末**，本轮落在
   正确阅读序位置）→ 净 −3 字（页码不再被当正文列画在正文区）。**根因是 `page_rows` 的
   「页外行须框外确有墨迹」判据用**固定灰度 185**（wz6 口径），而 wz7 纸底是 185-199 → 该判据
   恒不成立 → 页边页码/书耳一律被当正文行**（taskS 之前就存在，非本轮引入）。
   **选项**：(a) 现状（内容更正确，少 3 字页码）；(b) 把该判据改成按本页 Otsu 阈值（与 NF 其它
   路径同源）→ 页码归入「页外行」由 `note_puts_frame`/`special_tex` 渲染，需另开一轮验证
   （会动到所有 NF 页的行归属，影响面大，本轮未做）。
2. **列末 `[字][。][」]` 的「」不被修剪**（§3-③）：该列列底多约半格（渲染拉长 ~5%）。要修需要
   文本侧知道「列末还有一个引號」（OCR 没有）或放宽间隙阈值到 0.6-0.75 步进（会把真正的标点也误剔，
   本轮测过会伤 4 列），故保持现状。
3. **OCR 内容缺失（引號「」、书眉「金瓶梅」）**：属上游数据问题，管线内无法凭墨迹补字
   （凭空补字违反「判据不得放宽」）。选项：重跑该页 OCR（`useDocOrientationClassify` 那类参数
   与此无关，需查 OCR 服务的标点/引號识别），或接受现状。
4. **p55 列 x373.7 的 1 处空隙落位偏 1 格**：总格数对（2 格）、位置在「脾|恰」而非「，|不」。
