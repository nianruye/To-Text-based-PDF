# 目录（TOC）处理：识别与分流

> 2026-11-17 · 回答「系统对不同目录的识别是怎么实现的」
> 关联 AGENTS #55 / #56

## 1. 识别：哪些页是目录（`_TOC_PAGE`）

`build_geom.py` L721-743，**逐书一次，与形态无关**：

```python
# ① 书眉含「目录」且 ≤6 字的页
_mark = [页 if 前3行中有 startswith("目录") and len(t) <= 6]
# ② 标记页之间全部收（偶页无「目录」书眉）
_tocI = set(range(min(_mark), max(_mark) + 1))
# ③ 向后扩展：无书眉的续页，按「条目形态」判定
def _toc_like(rows):
    return 计数( 纯数字行 or 目录条目前缀 or 点线+页码行 ) >= 5
while _toc_like(下一页) and 扩展 <= 6 页: 收进来
```

**只判「是不是目录页」，不判「是哪种目录」。**

## 2. 分流：四条渲染路径（按优先级）

| 优先级 | 路径 | 触发 | 实际使用 |
|---|---|---|---|
| 1 | **结构化目录** L1074 | `structured_toc_pages` 配置 + LAYJSON | wz9（英文目录）|
| 2 | **分离式目录** L1101 | `toc_split_pagenum_pages` 配置 | wz10 |
| 3 | **`toc_pre` 片段** L1618/L1854 | `TOC_PRE=1`（默认）+ 该页能整理出条目片段 | **ghbq** |
| 4 | **普通文本流** | 其余 | **wz1 / wz3 / wz4 / wz8** |

> 实测依据：ghbq 的 tex 里有 20 处 `\makebox[36pt]`（路径 3 的页码右对齐）；
> wz1 的 tex 里 **0 处**，其目录字号精确等于 `FONT`（= 普通文本流）。

## 3. 各路径的字号来源

| 路径 | 字号 | 状态 |
|---|---|---|
| 1 结构化 | 独立设定 | wz9 专用 |
| 2 分离式 | **FONT × {1.02 章 / 1.0 节 / 1.12 编 / 0.83 续行 / 0.75 页码}** | ✅ PR #62 |
| 3 toc_pre | **FONT × {1.13 / 1.0 / 0.93 / 0.85 / 0.78}** | ✅ PR #63 |
| 4 普通流 | `FONT`（与其他正文一致） | 天然 |

**核心规律（三本实测）**：目录条目字号 ≈ 正文字号

| 书 | 源 TOC 墨高 | 正文字号 |
|---|---:|---:|
| wz10 | 16.92pt | 17.4 |
| wz3 | 12.96pt | 14.5 |
| wz1 | 7.20pt | 10.1 |

## 4. 目录参数自校准（`_TOC_CAL`，L745-785）

| 参数 | 用途 | 算法 |
|---|---|---|
| `font_line` | 条目字号（**注意有 ×1.15 经验系数，会过头**）| 行高中位 × FONT/H_BODY × 1.15 |
| `foot_x` | 页脚页码的 x 范围 | 底部数字簇分桶 |
| `title_max` | 标题最大字数 | 标题字数分布的 80 分位 |
| `toc_ref` | 缩进基准 | 非数字片段最左 x0 |

> `font_line` 目前**未被采用**（实测 ×1.15 使 wz10 得 19.1，而实际应 17.3）。

## 5. 仍未通用的两处

| 位置 | 现状 | 建议 |
|---|---|---|
| 路径 3 的三级缩进 | `0 / 33 / 66pt` 硬编码 | 按源 x0 相对基准 |
| 路径 3 页码框宽 | `\makebox[36pt]` | 按最长页码宽度 |

这两处目前只影响 ghbq（唯一走路径 3 的书），改动风险低但收益也低。

---

## 6. 为什么不做「按页自动选路」

2026-11-17 实测：给 wz1 p11 / wz3 p13 启用分离式路径（自动判定触发）后，
**行距被拉散、标题尺寸过大**，明显不如它们本来走的普通文本流。

**结论**：不是所有目录都该用同一套逻辑 —— 形态差异是真实的，
用配置显式声明比自动猜测更诚实（AGENTS #57 判据边界原则）。
