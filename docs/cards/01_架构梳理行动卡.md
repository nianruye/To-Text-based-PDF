- 已知调用方式：各管线通过命令行参数 + 环境变量驱动；fit_positional 通过 subprocess 调用 build_ 脚本
  - 代表性测试样本（仅作上下文，分析聚焦代码结构本身）：wz1.pdf（单规制）、wz2.pdf（双规制夹注本）、优化前.pdf、优化前2.pdf。架构梳理的对象是代码结构，不绑定特定 PDF 的页数或指标

## AI 动作

1. 只读代码，不改文件。
2. 列出 public API 和下游可能依赖的入口：
   - 每条管线的命令行参数约定（argv[1]..argv[n] 各是什么）
   - 每条管线读取的环境变量清单（os.environ.get() / os.environ[]）
   - 输出 PDF 的命名约定和路径
3. 拆出职责板块：
   - **几何标定**：cw（满行字数）、MEASURE（版心宽）、FONT（字号）、BASELINE（行距）、LINESPREAD（行距因子）——在 build_classic.py:L29-65 和 build_geom.py:L29-58 各有一份
   - **LaTeX 转义**：escape_tex / _esc_chars / esc ——在 build_pdf_v13.py:L41-46、build_classic.py:L200-233 各有一份
   - **标题识别**：_heading_core / _head_level ——在 build_geom.py:L67-78 和 build_pdf_v13.py:L1271 各有一份
   - **页码处理**：PN_RE / PAGENUM_GLOBAL_TABLE / 页码推断 ——在 build_geom.py:L59-63、build_pdf_v13.py:L683 各有一份
   - **书影图块**：detect_fig_bands / in_figure / extract_figs ——在 build_geom.py:L288-367 和 build_classic.py:L448-463 各有实现
   - **目录页**：group_toc_rows / TOC_ENTRY_RE / toc_map ——仅在 build_pdf_v13.py:L1163 和 build_geom.py:L86-96
   - **校准两趟**：render → measure_heights → ratio → 重渲 ——fit_positional.py 和 fit_positional_classic.py 完全相同（仅 L34 的 build 脚本路径不同）
4. 画状态地图：
   - **环境变量**（16个）：LAYJSON, PAGE_FONT, POSITIONAL, PER_PAGE_PITCH, LAYOUT_HEADINGS, OVERBOUND, FONT_SCALE, PUNCT_WEIGHT, REGION_LAYOUT, REGION_FONT_SCALE, PAGENUM_GLOBAL_TABLE, PAGENUM_OFFSET, TOC_HEADING_MAP, POS_FILL, VERIFY_MARK, POS_EST_LOG
   - **文件系统**：读取 data/{wz1,wz2}/*.json；写入 output/*.pdf；临时目录 /tmp/fitpos_*/
   - **外部命令**：xelatex（TeX Live）、python3 subprocess
5. 找出「几套真相」：
   - 三条管线并存：build_pdf_v13（重排 reflow）、build_geom（逐行几何还原）、build_classic（古籍专用，墨高重叠）
   - fit_positional × 2（仅 L34 不同，96行重复）
   - wz2 七条结算路径的等价物：本项目是两套校准驱动 + 三套渲染管线
6. 列出可疑行为：像 bug，但还不能顺手修（见下方清单）。
7. **符号解析检查**：对每个函数全文 grep 所有被引用的变量/函数名，列出**只有引用没有定义**的符号（如 FONT_HD、死参）。这类死代码不会触发运行时错误，靠"看起来可疑"的模式匹配发现不了，必须做跨文件引用追踪。

## 可疑行为清单（从源码通读确认）

| # | 可疑行为 | 源码证据 | 为什么不能顺手改 |
|---|---------|---------|-----------------|
| 1 | fit_positional.py 和 fit_positional_classic.py 仅 L34 一行不同，其余 96 行完全重复 | fit_positional.py:L34 = `'build_geom.py'`，fit_positional_classic.py:L34 = `'build_classic.py'` | 合并后如果参数传递不同，两条管线的校准可能同时崩溃 |
| 2 | PER_PAGE_PITCH 无默认值——不设时回退全局 BASELINE，静默退化为错误行为 | build_geom.py:L124 page_pitch() 中无 `os.environ.get('PER_PAGE_PITCH', '1')` | 历史上有 LINESPREAD 1.57x 低估 bug，这是同类问题 |
| 3 | build_classic.py:L690 附录标题合并条件从 `gap<阈值` 改成 `0<gap<阈值`，是补丁式修复 | PROJECT_SUMMARY 记录的"附录五标题丢失修复" | 改阈值可能破坏其他页的紧邻合并（gap<0 是分立元素不应合并） |
| 4 | _in_an 状态机阈值 45pt 写死在 build_classic.py:L798 | `gap<45pt` 是硬编码的魔法数字 | 不同文本的案注间距不同，换书就得改代码 |
| 5 | escape_tex 三份实现在 build_pdf_v13.py:L41、build_classic.py:L200、build_geom.py 中 | 三份实现的转义字符集可能不同步 | 改一处漏两处是必然的——至今没人对比过三份的转义表是否一致 |

## 禁止事项

- 禁止边读边改——先交付结构图，再谈重构
- 禁止把 escape_tex 的三份实现直接合并而不先锁测试——行为可能有微妙差异

- 禁止只看 Python import 依赖，忽略 subprocess.run 的运行时耦合
- 禁止把「LINESPREAD 默认值缺失」直接加默认值——先锁住不加默认值时的当前行为
