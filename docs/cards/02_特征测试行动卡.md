## 测试分层（三层，从稳定到易变）

```
第 1 层：单元测试 — 锁函数的输入→输出映射
  被测对象：独立函数（无 PDF、无 xelatex、无环境变量）
  稳定性：最高（函数逻辑不变，测试不坏）
  例子：escape_tex("$100 & 5%") → 应该输出 "\\$100 \\& 5\\%"

第 2 层：特征测试 — 锁管线的行为不变量
  被测对象：完整管线 或 可独立运行的子步骤
  稳定性：高（不变量不依赖输入文件内容）
  例子：任意 spotting 数据 → 脚注行字号 < 正文行字号

第 3 层：回归快照 — 锁特定输入文件的输出指标
  被测对象：完整管线处理特定 PDF
  稳定性：低（改代码可能改善指标，但快照测试会红）
  例子：wz1 pitch=95.3% — 这是快照，不是不变量
```

> **规则**：第 1、2 层必须先全绿，才允许 AI 重构。第 3 层是辅助参考，红了需要人判断是改善还是回归。

## 第 2 层：特征测试（管线行为不变量）

### 什么是不变量

不变量是「不管输入什么 PDF，只要数据格式合法，这条管线就应该满足的性质」：

| 不变量 | 适用的管线 | 怎么验证 |
|--------|----------|---------|
| **脚注行字号 < 正文行字号** | build_geom | 取脚注区域和正文区域的字号中位数，前者应 < 后者 |
| **段首行 x0 > 续行 x0** | build_geom | 取缩进行和普通行的起始 x 坐标中位数，前者应 > 后者 |
| **标题行字号 ≥ 1.2 × 正文行字号** | 两者 | 标题行的最大字号 ≥ 正文中位字号 × 1.2 |
| **输出页数 ≥ 源正文页数的 80%** | 两者 | 源 spotting 数据的 key 数量 vs 输出 PDF 页数（允许合并空白页，不允许大量丢页） |
| **输出 PDF 能被 fitz 正常打开** | 两者 | `fitz.open(out_pdf)` 不抛异常 |
| **无溢出（输出页数 ≤ 源页数 × 1.2）** | 两者 | 允许少量溢出（如跨页表格），不允许翻倍 |
| **正文行 pitch 方差 < 阈值** | 两者 | 同页内正文行间距的 CV < 30%（不能有的行挤在一起有的拉开） |
| **全书无乱码字符 ￿** | 两者 | 全文搜索 `￿`（LaTeX 转义失败的标记） |
| **环境变量缺失时有明确错误** | 两者 | 不设 PER_PAGE_PITCH → 不应静默降级，应打印 warning 或设合理默认值 |
| **页码在每页底部 ±5% 区域内** | 两者 | 提取最后一行的 y 坐标，应在页面 90%-98% 位置 |

### 与特定 PDF 输入的关系

这些不变量用**任意合法 spotting 数据**都应该成立。验证时可以用 wz1 或 wz2 的数据来跑，但断言不绑定 wz1=222 页这种具体数字。比如：

- ❌ `assert pages == 222` — 绑定了 wz1
- ✅ `assert pages >= len(src_keys) * 0.8` — 不绑定特定 PDF
- ❌ `assert pitch_rate == 0.953` — 绑定了 wz1 的指标
- ✅ `assert pitch_rate > 0.5` — 「行距不能崩」是不变量

### 完成标准

- build_geom 和 build_classic 各 ≥ 5 条不变量测试
- 每条测试的断言不包含特定 PDF 的具体数字（页数、pitch 值、字号值）
- 测试可以跑在 wz1、wz2、优化前.pdf 任意合法输入上
- 不变量可以从 spec 里反向推导出来（spec 说了「脚注小字」→ 测试就验证这个关系成立）

### 可复制 Prompt

```text
基于 build_geom.py 和 build_classic.py 的源码，请为每条管线生成特征测试。

**第 1 步：先写不变量 spec。** 通读源码，找出管线在每个处理阶段的行为不变量（排版规则、字号关系、位置约束），写成 spec 文档（每条不变量一句话 + 对应代码行号）。

**第 2 步：生成特征测试。** 根据 spec 写测试，特征测试锁的是行为**不变量**——不管输入什么 PDF（只要 spotting 数据格式合法），
这些性质都应该成立。不绑定特定 PDF 的页数、pitch 值、字号值。

请为 build_geom（现代书籍管线）列出至少 5 个不变量，例如：
  - 脚注行字号中位数 < 正文行字号中位数
  - 段首行 x0 中位数 > 续行 x0 中位数
  - 标题行最大字号 ≥ 正文中位字号 × 1.2

  - 正文行间距在每页内的 CV < 30%

对每个不变量：
1. 写一条测试函数，用 wz1 或 wz2 的 spotting 数据作为输入

   — 这仍然是关系断言，但锁住了现状范围
```

## 第 3 层：回归快照（辅助参考，不是门禁）

### 定位

这一层的测试记录**特定 PDF 在当前管线下的输出指标**。它们会随着代码改进而变化（改了 pitch 算法 → wz2 的 59.1% 升到 70% → 快照测试红了但这是好事）。

**因此这一层不作为 CI 门禁。** 只记录基线，供人对比。红了需要人判断是回归还是改善。

### 怎么做

- 取 wz1、wz2、优化前.pdf、优化前2.pdf 四个代表性 PDF
- 用当前管线生成输出 PDF，记录指标：pitch 达标率、空白页数、溢出页数、页数
- 存为 `src/test/snapshots/<管线>_<PDF名>_基线.json`
- 重构后重新生成 → diff 两个 JSON → 人判断变化是否可接受

### 不放在 CI 门禁里

这层测试**不作为 required check**。CI 可以跑它并报告"快照变化"但不会标红。标红与否由人在 PR 里决定。

---

```text

**第 2 步：提取基线指标。** 从现状 spec 中提取可量化的指标，存到 src/test/snapshots/ 目录：

  - source_pdf/wz1.pdf（现代学术著作，222页，脚注+标题层级）→ build_geom 管线，作为**现代书籍**基准
  - source_pdf/wz2.pdf（横排夹注本，783页，旁注/墨高重叠/案注/附录）→ build_classic 管线，作为**复杂注释排版**基准
  - source_pdf/优化前.pdf（现代书籍，简单排版）→ build_geom 管线，作为**现代书籍**基准

对每份输出 PDF 记录以下指标（用 verify_geom.py 的同口径测量）：
  - pitch 达标率（误差 <3% 的页占比）

  - 溢出页数

基线 JSON 格式示例：

要求：
**输出**：现状 spec 写入 `spec/snapshots/` 目录（每份 PDF 一个 spec 文件）。基线 JSON 写入 `src/test/snapshots/`。

- 这些快照不作为 CI 门禁（放在 src/test/snapshots/，不加入 pytest）
- 重构后重新生成 → diff 两个 JSON → 人判断变化是否可接受
- 压力测试样本的指标变化（如 wz2 pitch 59.1% → 55%）需要人工判断是回归还是可接受的代价
```

## 完成标准

- 第 1 层单元测试：每个独立函数 ≥ 1 条测试，不依赖文件系统/外部命令，跑一次 < 1 秒
- 第 2 层不变量测试：build_geom 和 build_classic 各 ≥ 5 条，断言不绑定特定 PDF 的页数和指标
- 第 3 层回归快照：代表性 PDF 的基线指标已记录到 src/test/snapshots/
- 所有测试连续跑 3 次结果一致（无环境变量泄漏、无随机数影响）
- spec 和测试说的是同一组现状：spec 中描述的行为在测试中能找到对应断言

## 禁止事项

- 禁止把「wz1 pitch = 95.3%」写成特征测试 — 这是快照，不是不变量
- 禁止用「应该是」写断言 — 不变量也应该是「当前满足 X 性质」，不是「理想中应该满足 Y」
- 禁止用具体 PDF 的页数作为断言 — `assert pages == 783` 绑死了 wz2
- 禁止在测试不稳定时开始重构
- 禁止只测 happy path — 边界输入（空 spotting 数据、单页 PDF、全图 PDF）也要覆盖
