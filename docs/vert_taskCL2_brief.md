## ② 行尾「一」未被转成闭引号 ﹂

### 现象（实测 p444）

源 OCR 数据该行文本：

```
x649.1  「溟冷飢鬼揮鍾馗。一」      ← 尾字「一」实为竖排闭引号 ﹂ 被 OCR 读错
x560.9  「一縣官貪污更堪嗟，」      ← 行首「一」实为开引号 ﹁
```

产物：行首那个**已正确**转成 `﹁`（在 x558 y342），行尾那个**没转**，产物文本仍是 `溟冷飢鬼揮鍾馗一`。

即：`_qfix`（§1.997，`VERT_QFIX`，日志 `[引號判别]`）处理了**行首**，**行尾这一侧漏了**。

### 必须查清的

1. `_qfix` 的候选生成是否只看行首？行尾为什么不进候选？（先打印行尾候选的墨迹三判据实测值再说）
2. 行尾那条墨在源图上是**列底**（该列 y600-830，尾字后 y830 以下无墨 → 说明 ﹂ 就落在尾字**自己那一格内**，不是额外的格）。这与「﹁ 占整格」同族，请复用 taskU-B 的结论（引號占整格，`_trim_marks` ④ 已修）。
3. 逐字判据请复刻行首那一侧已验证的口径（墨高/墨宽/竖画位置三判据 + 墨高上限 0.60×字高 + 位置闸门），**不要重新发明**。

### 验收

- p444 产物文本尾字变 `﹂`（x 不变、y 不变、字数不变）
- 全书 `﹂` 计数上升、`﹁/﹂` 失衡从 +923 收窄；`verify_vert` 仍 PASS
- 逐页字符量**不许有减少页**（只是码位替换）
- **误改率必须量**：随机抽 30 处判为 ﹂ 的，回源图裁图核对（脚本落 `tmp_vert/cl2/qfix_tail/*.png`），误改率须为 0；任何一处存疑就如实登记不改

## ③ 诗句上下两段的 y 起点不一致 / 被压缩

### 现象（实测 p444，同一首诗的三列）

源书（OCR 行自己的 y 范围）：

| 列 x | 段 | 源 OCR y | 字数 |
|---|---|---|---|
| 647.4 | 上 | 332.5-547.0 | 9 |
| 649.1 | 下 | 603.1-830.6 | 9 |
| 560.9 | 上 | 331.1-544.1 | 9 |
| 561.8 | 下 | 600.2-804.7 | 8 |
| 517.7 | 上 | 348.4-544.1 | 8 |
| 517.7 | 下 | 600.2-829.1 | 8 |

**源书三段下半句的起点严格对齐在 y600.2 / 600.2 / 603.1（极差 3pt）。**

产物（同样三列，首字 origin_y）：

| 列 x | 段 | 产物 y | 步进 |
|---|---|---|---|
| 662 | 下 | **614** | 26.3 |
| 564 | 下 | **608** | 25.5 |
| 530 | 下 | **584** | **21.7** ← 被压缩，末端 736 vs 源 829 |

下半句起点极差 **30pt**；x530 那列的字步进 21.7 vs 源 32.7（压缩 34%）。

### 已定位的根因（主控实测，请先证伪再动手）

**子槽的 `top/bot` 来自槽窗口内的局部墨迹 run 统计，比 OCR 行自己的 y 范围不可靠。**

- x530 下句：子槽 584-765（跨度 181），而 OCR 行 600.2-829.1（跨度 229）→ 两端都不对
- 现有 `ROWCLIP`（`VERT_ROWCLIP_SPAN`）只处理「槽比行大得多」的情形（收缩），
  **「行比槽大」这一侧没有出口**：
  - 收缩判据 `_B1-_T1 < 0.75×槽跨度` 对 x530 是 `177.8 > 135.8` → 不触发
  - 量级判据 `槽 > 1.6×(字数×步进)` 是 `181 < 277.7` → 不触发
  - 于是槽 584-765 原样使用 → 压缩

### 请评估的方案（择一或自提）

**方案 A：配对后「行 y 权威」** —— 把子槽的 top/bot 直接设为 OCR 行的 y 范围
（`top = row_y0 - pad`, `bot = row_y1 + pad`，`pad = 0.5×step`），
仅在行的 y 范围**明显不可靠**时（如行是高/宽比异常的合并残片）才保留槽值。

- 风险：这会影响**全书每一行**的落位（不是只影响特殊行）。必须给 env 开关（默认关 → 先量），
  并用「逐页文本 + 列位审计 + 墨迹覆盖率」三把尺子对照开/关两版。
- 先验：p444 三列下半句起点极差应从 30pt 降到 ≤5pt；x530 步进应回到 ~28-33pt。

**方案 B：子槽 y 只用「本槽 x 窗口内的墨迹 y 投影」，但把窗口夹到 OCR 行的 y 带内**
（即先按行 y 定搜索范围，再在范围内找 run 边界）。改动小，但只对「槽大于行」有效，
对 x530 这种「槽小于行」仍无效。

**方案 C：`_split_slot_y` 拆完子槽后，用「配对行的 y 带」做一次夹取/外扩双向校正**
（外扩时上限 = 父槽的完整跨度，防止串到别的内容块）。

推荐先做 A 的开关版，用全书量数字说话。

### 验收（三把尺子缺一不可）

1. **p444 单页**：三列下半句首字 origin_y 极差 ≤5pt；x530 列步进 ∈ [28, 34]pt
2. **全书 `check_poem_blocks.py`**：违规数从当前 **162 处**下降（该工具已双向标定：已知好页 p85/p86/p100/p300 必过、已知坏页 p444/p90/p225 必命中；**判据不许改**）
3. **逐页字符量**：与当前基线**逐页相同**（这一条只动位置，不动内容，任何减少页都是 bug）
4. **`vert_layout_audit.py`**：列位异常 ≤ 170 / 强错位 ≤ 20 / 列间重合 ≤ 3（不许变差）
5. **`verify_vert` PASS**
6. **wz6 零回归**：`vert.tex` md5 必须仍为 `c2fdfa0e63614e61364a74f02d13ac1d`
7. **451+ 单测全绿**（新增开关必须配正向测试，且测试要能被否定面打红）
