# battle17 · OCR 模式对照实验（layout+ocr / spotting / 条带+layout）

## 0. 结论（先行）

1. **C（8 列条带 + layout+ocr）失败**：22 列被读成 **15 个块**、块序乱、跨列合并（如 `「駐雲飛」「悶倚欄杆…` 一块含两列）→ **LCS 覆盖率仅 0.311**。条带页的身份不能被 layout 模式稳定保持。
2. **D（单列窄条 + layout+ocr）基本成立但代价高**：22 页中 **21/22** 列读出，单列文本与 OCR 行 LCS 0.92–1.00、全书级 LCS **0.989**，引号大多保留（8 开/5 闭 vs 源 8/8；3 处闭号丢）；**1 列空**（h=65pt 的极短列）；曲牌名 5/7 带〔〕。**按 22 页/原页 → 整书 38,456 页**。
3. **A（整页 layout+ocr）正文最完整**（LCS **1.000**）、引号大多正确（开 10/闭 9 vs 源 8/8；多出的开号来自**曲牌名被读成「画眉序」**）、曲牌括号 4/7，块级 bbox 只有 **11 块 vs 22 列**（几何偏粗）。
4. **B（整页 spotting，现用）**：列 poly 完整，但**引号全变「一」（0/0）**、曲牌括号 0/7；LCS 0.993。
5. **E（False + promptLabel='ocr'）**：API 支持（block_label=`ocr`），正文 LCS 0.996，但**引号全丢（0/0）**、曲牌括号仅 1/7 → 不能单独做前端。
6. **建议：A + B 双模式**——A 出文本（正文最完整、引号/括号最好），B 出列级 poly（几何可靠），再跑现有后处理（`「名」`→`〔名〕`、`一`→`「` 源墨判据）。成本 **3,496 页/整书**（1,748×2），远低于配额 4 万页/天。**C 弃用；D 只在个别引号问题页做兜底**（单页 22 倍成本）。

## 3. 核心假设验定（C/D：窄条 + layout 是否仍读对「」且不丢字）

- **C（8 列/页）：不成立**。布局模型把多条窄条当成相互重叠的版面块：22 列 → 15 块；块内容跨列（`「駐雲飛」「悶倚欄杆…` 同块）、顺序错乱（`畫眉序` 排到最前、`鎖南枝` 排到最后）、`要孩兒/紅綉鞋` 等列缺正文；LCS 0.311。**条带身份 ≠ layout 块身份**。
- **D（单列/页）：基本成立**。21/22 列读出（唯一空的 pg20 = 列高 65pt 的极短列，疑似低于 layout 最小可读尺寸）；读出列与 OCR 行 LCS 0.92–1.00；引号保留（8 开/5 闭，3 处闭号丢）；曲牌括号 5/7。**单列条带的身份可靠**，但一列一页的代价是 22×1748 = 38,456 页/书。
- 结论：**窄条方案只能用单列（D），不能用 8 列拼页（C）**；D 的代价使其只适合做兜底或对少量问题页使用。

## 4. 典型错误样例

- **A**：`「畫眉序」「自會俏冤家…`、`「傍粧臺」「到如今…`（曲牌名被读成引号对，源为`〔畫眉序〕`/`〔傍粧臺〕`）；`紅綉鞋「水面…`（缺 `〔〕`）；引号计数 10/9 比源 8/8 多 1 开号。
- **B**：`一惜花人何處`、`一呀！`、`一水面上…`（`「`→`一`）；`畫眉序`、`紅綉鞋` 裸名无括号。
- **C**：块序 `〔畫眉序〕 → 「呀… → 「駐雲飛」「悶… → 〔金字經〕…`（源顺序相反）；`「鎖南枝」「紗窗…` 一块含两列；`要孩兒`/`紅綉鞋` 列正文缺失（仅剩名）。
- **D**：`〔金字經〕「惜花人何處…」` ✓；`「駐雲飛」「悶倚欄杆…`（名入引号）；`「呀！…` 缺闭号；pg20（h=65pt）空。
- **E**：`〔金字經〕惜花人何處…`（开引号被吞）；`駐雲飛`、`畫眉序` 裸名；全篇 0 引号。

## 5. 建议（下一版 OCR 前端）

1. **主方案：A + B 双模式**
   - **A**（整页 layout+ocr）作为**文本来源**：正文 LCS 1.000、引号 10/9（仅 2 处曲牌名被写成引号）、曲牌 4/7；配合现有 battle16 后处理：
     - `「X」`（X 为 2–4 汉字曲牌名）→ `〔X〕`（已在 `_fix_bare_cuv_names` 实现）；
     - 缺括号的裸名 → 按名表补（battle15 已实现）；
     - 多出的开号/闭号用源图墨迹判定清理（battle16 `_collapse_quote_noise` 可复用）。
   - **B**（整页 spotting）作为**几何来源**：保留逐行 `rec_polys`，列 poly/列序可靠（现管线即用）。
   - 成本：1,748×2 = **3,496 页/整书**（用户配额 4 万页/天，占比 8.7%）。
2. **备选：A 单模式**：若块 bbox 能拆出 22 列（A 只有 11 块，需按块内文本行数/坐标再切分），可省一半页数；风险是几何精度。
3. **弃用 C（8 列条带 layout）**；**D 仅作兜底**（个别页引号问题、且单列可读），成本 22×页数，按需少量使用。
4. **E 不适合**（引号全丢）；但说明 `promptLabel='ocr'` 在 `useLayoutDetection=False` 下**被服务端接受**（label=`ocr`），可作为「只要正文、不要引号」场景的选项。
